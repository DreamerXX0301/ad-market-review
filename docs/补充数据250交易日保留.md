# 补充数据的250交易日保留

本策略只处理盘面补充，不缩短个股、指数及板块K线的五年行情窗口。版本为 `supplement-retention-250-v1`，只对明确冻结该版本的新手动任务生效；旧任务恢复时继续使用原范围。

## 保留范围

以本次成功发布的观察日为 `anchor_date`，使用已核验的市场交易日历，**含观察日本身向前保留250个交易日**。第250个交易日为 `cutoff_date`，并非250个自然日，也不是根据文件时间推算一年。

| 数据 | 逻辑保留规则 |
| --- | --- |
| `public_pools` 涨跌停等公开池 | 日期不早于 `cutoff_date` |
| `fund_flows` 资金补充 | 日期不早于 `cutoff_date` |
| `sector_index_history` 板块指数盘面日快照 | 日期不早于 `cutoff_date` |
| `annual_pools`、`annual_down_pools` 年度涨跌停统计证据 | 250交易日窗口与观察日所在自然年取并集 |
| 个股、指数、板块K线及其来源链 | 使用独立五年行情规则；不由本策略裁剪 |

日历不足250个交易日、日期无效或观察日不在已核验日历中时，不补造日期，也不执行本轮逻辑裁剪或物理清理。年度统计仍按真实覆盖判断，缺口不会因保留策略变成零。

逻辑日期范围不等于物理文件占用上限。以下证据有独立用途，可能超过250个交易日：

- 当前 `head.json` 的完整依赖，以及按 `created_at_ms` 排序最近两份索引的依赖。最近两份通常包含当前索引，并非额外保留两份旧索引。
- 已持久化业务引用指向的旧行情代际，其补充索引和递归依赖继续保留。
- 当前自然年的年度涨跌停统计原始证据。
- 全部已验收 `sector-chart`、`sector-chart-tail` 记录及其原始响应、完整/基础/尾部引用链，作为独立K线来源保留。
- 元信息不足以判断日期的记录，按保守保护处理。

历史页面从当前索引读取其保留的逐日补充对象，不需要保留近250天的每一整套旧索引。否则旧索引各自再引用250天，会把实际物理范围重复拉长。仍被业务证据或K线链引用的旧对象不受这一简化影响。

## 发布和清理顺序

1. 唯一worker先完成补充采集和校验，在年度覆盖计算前裁剪本次待发布文档。
2. 补充索引成功发布后，才执行物理清理；采集或发布失败不执行清理。
3. 在业务目录的进程间排他锁下，读取并核验文件依赖图。API完整补充读取、标准备份与其他相关消费使用共享锁。全部HTTP业务写请求从进入处理、解析参数直到事务和响应/后台工作完成，也持有共享锁，避免新任务或新业务引用落在“最后一次核验之后、删除之前”的间隙。
4. 先保护全部保留根，再递归追踪 `artifact + sha256`、`record_ref + sha256`、`*_artifact + *_sha256` 和板块薄索引的基础/尾部依赖，只规划确定没有保留引用的对象。
5. 在业务SQLite短事务登记不可变scope和逐文件SHA、大小、相对路径；事务外再次核验文件身份与SHA后删除。每个文件分别保存回执，最后记录完成。

清理不联网，不按目录年龄删除，不删除未知路径。符号链接、损坏SHA、缺失依赖、未知存储格式或引用不确定时，本轮停止并写入警告，不将已成功发布的行情改为失败。

除本任务外存在排队、运行、暂停任务或恢复租约，或存在备份pin时，本轮跳过，以保护恢复与备份证据。长规划后及删除前重新核验任务、业务引用和pin；变化时停止。worker心跳和本任务租约续期若未改变完整保护范围，可以继续，不会因每15秒心跳导致长扫描反复中断。

业务引用扫描仍读取全部相关业务表的 `snapshot` / `*_json` 字段，包括旧版及自定义标识、嵌套字符串和保守子串匹配。匹配表达式按标识的共同前缀分组，减少大JSON中无关位置的重复比较；不缓存业务保护结论、不跳过表，也不改变最长匹配及 Unicode 转义保护全部已知代际的规则。心跳触发的复核继续重新读取业务引用，并保留前后 `data_version` 检查。

任务进度将“发布补充数据索引”与随后“核验补充数据保留引用”分开。清理回执另记业务引用扫描总毫秒数、调用次数和文件依赖规划毫秒数；已经写入 `head.json` 的时间不能用整个清理阶段的结束时间替代。

统一HTTP锁覆盖 `POST/PUT/PATCH/DELETE`。另外两类已有GET会写业务库，也显式纳入：`GET /api/v1/watchlist` 修补旧自选加入基准，`GET /api/v1/research/jobs/{id}` 续期研究缓存和pin。任务进度、健康检查与普通只读GET仍可读取，不因业务写锁而占用异步事件循环。

仅 `POST /api/v1/tasks/{id}/pause` 和 `.../cancel` 精确豁免，保证清理持排他锁时仍可停止任务；这两个操作不会取得新输入或创建引用。`resume/retry` 和新建任务仍必须等共享锁。等待清理锁时以非阻塞方式轮询并检查任务guard；扫描每128个对象及拓扑选择每个有界批次也检查guard。暂停/取消保持原语义并释放派生图，不转成采集失败。

HTTP锁等待取消会回收文件描述符。若同步线程已经开始业务SQLite连接或补充读取，则用线程安全引用计数保留共享锁：在 `ensure_ready` 之前开始连接保护，覆盖提交/回滚与实际连接关闭；读取保护覆盖实际文件消费。HTTP外层及内部异步任务即使连续两次被取消，也不会把“Task已结束”误当成同步SQL线程已提交。最后一个实际连接/读取scope退出后才解锁；已结束的请求不得开始新的业务连接或补充读取，避免晚到线程借用已复用的文件描述符。worker心跳等没有HTTP上下文的连接维持原行为，不额外取共享锁。

## 预算、恢复和容量边界

- 单次清理最多 **4,096个文件、256MiB逻辑字节**，任一上限到达后保留余量，后续手动增量继续消化。该预算能覆盖800个板块各产生验收记录、规范对象、原始响应的约2,400个每日对象。
- 文件清单按父引用先于子对象安排；被本轮预算排除的父对象会继续保护其子对象，避免批次之间留下断链。
- `supplement_retention_run` / `supplement_retention_file` 保存 `planned → deleting → completed` 和逐文件 `planned → removed/absent` 回执。暂停、取消和中断不自动继续；显式恢复使用原scope，不能扩大删除授权。
- 若进程在删除后、写SQL回执前中断，恢复时以 `absent` 记录零次新增删除，避免重复计算释放量。已完成任务核验原scope与head后直接返回，不再重扫全图。
- 依赖图是可丢弃的临时SQLite文件，缓存8MiB、临时表落盘、mmap关闭；不把百万节点及边同时放入Python内存。实际collector显式使用worker工作卷下的 `.supplement-retention` 私有0700目录，拒绝目录符号链接；计划关闭、暂停、异常时清理派生图。硬kill或断电不能执行finally，可能留下可丢弃的私有派生图，不能承诺此时零残留。Docker worker的 `SQLITE_TMPDIR` 也指向持久工作卷，SQL排序等临时文件不会落到 `/tmp` 的tmpfs占用内存；有界选择表直接存入同一派生图。独立只读诊断planner默认使用系统临时目录，不向真实来源树写文件。来源依赖LRU只保存小元数据及引用，最多32,768项或估算32MiB，不保存完整响应树。
- 每个JSON对象核验上限64MiB；扫描预算为200万个文件、1,000万条边，派生图磁盘上限2GiB。达到预算时安全停止并提示，不继续冒险删除。五年K线来源链、长期业务引用可能使文件量超过单纯“250天补充”估算；这些例外必须另行评估，不能承诺所有磁盘占用恒定。

回执中的字节是逐路径逻辑大小，不代表文件系统立即释放的物理空间，也不是运行内存。SQL审计随标准业务备份保留；审计本身不会成为补充对象的永久业务引用根。

SQL审计的scope和逐文件SHA回执仍随历史操作积累，不属于按250交易日滚动的原始补充payload。保留策略不承诺业务库和全部磁盘占用零增长，也不能据此编造未来一年或五年的固定GB数值。

## 验证与测量

以下为本轮本机测量，耗时受机器负载、文件缓存和数据规模影响。所有真实数据测量只读，未删除来源文件，未发起网络取数。

| 检查 | 结果 |
| --- | --- |
| 真实补充树 | 21,659个JSON，526,884,093逻辑字节；保守保护所有已知行情代际 |
| 真实规划候选 | 1,254个无引用对象、38,263,980逻辑字节，单轮预算可全部容纳，余量0 |
| 真实读验规划耗时 | 冷缓存27.202秒、进程依赖缓存命中后2.363秒；派生图40,062,976字节，进程峰值约284.19MiB（包含行情模块导入、JSON解码等） |
| 来源一致性 | 冷暖scope SHA一致，`head.json` SHA未变，实际删除0 |
| 十万节点合成容量 | 100,259个已验证节点；Python图增量峰值约5.46MiB，派生图约71.3MiB；含tracemalloc测量11.71秒 |
| 百万节点合成容量 | 1,000,259节点、约50万条边；规划31.79秒，进程峰值约90.19MiB（基线79.22MiB），派生图约711.13MiB |
| 800板块单日回退 | 真实临时JSON及ledger验收；至少2,400个对象可在默认预算内全部清理；320文件后暂停、原scope恢复，逐文件与逻辑字节对账一致 |

百万节点容量使用合成已验证node loader，用于核验派生图内存和SQL复杂度，**不包含真实文件读取、JSON解码与SHA核验**，不可当成百万真实文件的端到端耗时。真实规划包含上述来源读验，仍为全树扫描；它不是整次增量耗时，也不是已经实现了增量DAG登记。

增量SQL阶段另在193个真实观察日、同一行情代际上对账：原全量物化6,239,565行，调整后1,061,087行；物化阶段从1,579.454ms降至189.822ms，约缩短88%。所有日期选价SHA一致，`EXCEPT ALL` 差异0；逐日期读取合计1,352.759ms与1,219.290ms。**这只是本地报价物化及日期签名阶段，不包含供应商等待和整次盘后增量耗时**，不能解释为盘后更新整体提速88%。

对应本地验收工作文件为 `data/work/runtime/hot-retention-next/retention-readonly-disk-graph.json`、`data/work/runtime/supplement-graph-capacity-{100k,1m}.json` 和 `data/work/runtime/overnight-20261025/supplement-quote-benchmark.json`；这些文件被Git忽略，不属于发行内容。

安全测试覆盖：250交易日含anchor边界、年度例外、日历不足、共享依赖、旧业务代际、板块基础/尾部/压缩字段链、预算截断后的幸存图、未知路径与SHA损坏、转义JSON键、符号链接、任务/pin/业务引用变化、心跳续期、暂停恢复、删除与SQL回执之间中断、幂等重入、十万/百万节点容量及800板块单日对象吞吐。

HTTP互斥回归使用独立collector进程，停在真实 `Path.unlink` 调用点后发起实际任务入队路由：写请求必须等待，SQLite中尚未出现新queued任务；同时GET进度和健康检查仍可读。另覆盖HTTP暂停/取消穿过排他锁、扫描和等待读者期间响应guard、异步锁等待取消、延迟open回收、同步提交期间的HTTP取消、原响应码/JSON/headers兼容、只读published目录，以及私有work图目录清理和符号链接拒绝。

反向回归让实际HTTP路由在提交前持有共享锁，collector必须等待；提交完成后读取保护根时能看到新queued任务并跳过，原补充树完全保留。正常HTTP、取消后同步提交和标准响应后台工作均受保护。双取消回归使用真实SQLite事务、真实补充读取及独立进程排他锁探针，确认实际提交/关闭或读取结束之前排他锁不能通过，并验证结束后新增连接/读取拒绝。新增带业务副作用的GET需要加入显式审查名单；历史候选回放GET应保持只读，手动留存通过POST受统一锁保护。

公开文档仅记录方法与汇总。原始测量JSON、运行日志和真实响应位于忽略的本地运行目录，不随源码发布。

## 业务引用扫描候选（尚未部署）

在同一份2,598,985,728字节的冻结只读业务库上，原版与候选均完整扫描1,112,921个业务字符串。原版平铺正则的首次测量中，字符串匹配占122.106秒，是131.924秒总扫描的92.6%。候选只将已知标识的前8个字符按公共前缀因式分解，递归深度最多8，仍保留字面字符、左起最长非重叠匹配和Unicode转义保护规则；超长及旧版自定义标识不增加递归深度。

| 同一冻结输入、含cProfile开销 | 新进程首轮 | 同进程第二轮 |
| --- | ---: | ---: |
| 原版完整业务引用扫描 | 131.924秒 | 137.882秒 |
| 保留的前缀树候选 | 28.441秒 | 28.363秒 |

两轮完整scope逐项一致，7个受保护行情代际、保护签名均相同，平均约4.75倍。OS文件缓存没有清空，不能称为冷盘基准；候选首轮可能与短小测试重叠，第二轮独占。冻结库中一个后来已成功的策略任务仍留有过期租约，诊断代理仅屏蔽这一入口阻断条件，以重放补充完成时的情境；所有业务引用保持原样，实际产品清理gate没有改变。没有执行物理清理、写入正式库或运行生产任务。

真实旧链路的“发布补充数据索引”事件到任务完成相隔314.324秒，但`head.json`在事件后1.126秒已经发布；其余313.198秒属于发布后的保留检查及收尾，不能全部记为索引写入耗时。候选为这两个阶段分别展示进度，并记录引用扫描次数/毫秒数和文件规划毫秒数。原来的`warn`诊断等级不符合SQLite的`warning`约束，可能使失败回执被吞掉，现已改正并验证告警能够落库；缺失的历史细分回执不能补造。

本轮相关208项回归包含旧/新冻结任务、暂停取消、代际变化、拒绝停发、来源SHA和完整覆盖对账、引用变化、字面前缀/特殊字符/非ASCII/万字符标识、空集合、恢复与预算。候选尚未部署；引用扫描提速不等于整条盘后增量已经以该耗时运行。
