# 交付与验收

本页提供可重复执行的检查入口，不把某台机器、某次历史任务的通过数量当成当前版本保证。产品功能见[README](../README.md)，数据覆盖见[实现范围与数据边界](实现范围与数据边界.md)，已有安装更新见[版本升级与回滚](版本升级与回滚.md)。

## 交付内容

源码包括前端、后端、锁定依赖、增量数据库迁移、部署配置、备份/恢复及验证脚本。运行行情、业务数据库、数据源 Key、主密钥、备份、依赖和构建缓存不应包含在源码发布包中。空安装不预置假行情、候选、跟踪或权益。

发布应记录源码 commit、镜像摘要（如实际发布镜像）、构建命令及检查结果。公开报告只保留脱敏后的摘要，不能原样上传本机业务记录、凭据、路径或供应商授权数据。

## 离线检查

在仓库根目录安装后端依赖：

```bash
cd backend
uv sync --frozen
.venv/bin/python -m pytest tests ../scripts/test_deployment.py ../scripts/test_upgrade.py -q
```

测试包含规则三态、日/周/月周期、历史事件、板块与个股隔离、指标和缺口、来源归一化、跟踪生命周期、回测账本、任务、备份恢复等。本轮还覆盖批量筛选后入池的断点与幂等、自选基准冻结、划线价基准和逐日提醒、人工上市身份审计、缺口诊断及来源核验的任务隔离。依赖真实已留存数据的用例可能按前置条件跳过；必须同时查看通过、失败和跳过原因，不能把跳过算验收成功。

在仓库根目录核对公开 schema 导出：

```bash
backend/.venv/bin/python scripts/export_schema.py --check
```

该命令在临时数据库应用全部迁移，只比较结构，不读取或升级现用业务库。新增迁移的升级测试还应证明旧行保留、新表不预置用户记录。

前端检查，在 `frontend/`：

```bash
npm ci
npm run format:check
npm run build
find src -name '*.test.mjs' -print0 | xargs -0 -n 1 node
```

`build` 包含 TypeScript 检查。辅助用例验证排序与 null、日期隔离、周期标签、规则/政策往返、历史事件绑定、搜索类型、图表偏好、五项摘要、自选和任务进度；不代表浏览器真实点击与视觉布局已验证。

## 已初始化实例的只读检查

先按[部署文档](部署与运维.md)启动待验实例；选择自己的隔离候选数据，而不是未经备份升级现用库。完整性检查在 `backend/` 执行，使模块路径与启动方式一致：

```bash
cd backend
.venv/bin/python -m app.cli validate
```

它检查 SQLite 完整性/外键、已发布 manifest 和产物 SHA；只在明确的目标数据目录上运行。它不证明供应商历史全齐，不会补拉缺失日期。

前端真实数据 API 审计，在 `frontend/`：

```bash
npm run check:api
```

默认访问 `http://127.0.0.1:8788/api/v1`。候选实例可显式指定完整前缀：

```bash
SHIXU_API_BASE=http://127.0.0.1:8789/api/v1 npm run check:api
```

该脚本只读，不配置来源、创建同步或执行策略；要求目标实例已有真实初始化数据。报告写入 `frontend/api-contract-checks.json`。报告中的实际查询日期、计数与脱敏状态需要人工复核，不应直接携带个人业务内容发布。

## 隔离 Docker 验收

需要 Docker 与 Compose。以下命令从仓库根目录构建本次待验源码；不是现用实例升级命令：

```bash
docker build -f deploy/Dockerfile -t shixu-workbench:validation .
backend/.venv/bin/python scripts/validate_container.py --image-tag validation --report container-validation.json
```

脚本建立唯一的新 Compose 项目、空数据卷和临时测试主密钥，核对健康接口、前端托管、空库无假候选、SQLite 版本、非 root、只读发布卷、API/worker 共享边界、业务写入、备份与新项目恢复。结束只清理自己的容器和卷，不挂现用数据或来源凭据。

容器测试不请求供应商，不能替代真实初始化、跨日增量或来源权限验收。脚本摘要与最终镜像应对应同一源码及前端构建；源码变化后不得沿用旧镜像通过记录。

## 手动验收清单

| 场景 | 通过标准 |
| --- | --- |
| 首次空库启动 | 无假行情和候选；来源验证及初始化均由用户手动触发；权限缺项有明确说明 |
| 首次 / 盘后同步 | 默认窗口来自元数据，进度/日志为真实阶段；板块首次完成后不再允许整库初始化，18:00后手动增量追加尾部，暂停/取消不自动继续 |
| 日期与数据覆盖 | 盘面日期只影响盘面；每页显示实际范围。旧日期成员缺档保持未知，不把最新成员或未完成周/月柱冒充历史 |
| 图表 | 日/周/月切换、MA偏好、缩放、十字线和副图值可用；菜单键盘与Escape不误关父弹窗，换页不残留菜单；五项摘要按今日、30日、最近涨停、年涨幅、年涨停顺序，严格截至观察日 |
| 个股与板块策略 | 独立目标、定义、运行、候选与跟踪；日/周/月标签和依据一致；股票范围和个股字段不会进入板块规则 |
| 编辑与取消 | 打开既有复杂规则/政策后取消，不发送隐式保存；嵌套组和旧无周期叶不丢失，历史事件绑定互不串联 |
| 策略与跟踪 | 命中依据可核对；重复入池不重设基准；提醒后继续跟踪，结束/移除留记录；缺数据不以0触发 |
| 已保存结果与运行反馈 | 切页和刷新恢复原已保存结果并标日期/版本；运行中及失败保留上次结果；活动任务名称、排队与阶段可见，有真实0进度也显示，无可靠百分比不伪造 |
| 批量执行并跟踪 | 全选限当前个股/板块类型；逐策略筛选后自动入对应池；展示命中、加入、跳过及其中忽略数，失败一项不阻断其他项；刷新不重新创建批次，暂停/恢复不重复已完成步骤 |
| 自选与加入涨幅 | 各入口可收藏；已有项不重置加入日/原价/来源，原策略事件价另存；移除不影响跟踪；缺报价或无法统一公司行动口径时涨幅未知，来源和代码可查 |
| 水平线与提醒 | 同股可保存多条命名线；换股/周期/价格口径不串线；旧线不自动启用。检查压力突破/触及、支撑收回及失守的等号与严格前一市场日；失守不自动新增自选，固定锚无证据保持未知 |
| 划线中断与补跑 | 规则生效前不追溯；离线多日保留实际触发日，补跑收藏使用当前加入日和收盘；同事件不重复收藏，删线/改规则后旧任务不能提交，暂停/取消不自动复活 |
| 上市身份 | 名录、已上市、待上市、未知分开；人工证据与来源日期分开。重复/无效/仅原始文件有记录不能证明无报价；新head重新核验，来源正式上市日优先，不用首根报价造日期 |
| 共用缺口诊断 | 日K与分析行情引用同一报告；可查连续无报价区间、原始记录及前后报价。GET不扫描历史或联网；显式来源核验有范围/进度/原始SHA，空响应不称已证实停牌，不改旧发布 |
| 覆盖语义 | 区分任务结束、文件结构核验、当前范围比例与来源完整性；未提供总量不展示完整百分比，真实不足100不四舍五入成100，100也不能扩大为所有历史已齐 |
| 搜索与成员 | 顶部可区分股票/指数/行业/概念；当前成员采集日与行情日分别显示，历史缺档不回填；成分股浏览不附板块事件价或自动入个股池 |
| 研究与回测 | 指定标的后才查询材料；历史报告按截止日查看；回测独立区间、七项统计及账本可核对，不支持/身份不足时明确拒绝 |
| 深浅主题与窄屏 | 涨红跌绿、未知清楚；表格横向滚动、筛选、弹窗层级、键盘搜索/Escape和股票连续浏览正常 |
| 备份与升级 | 备份可在新目录/新卷恢复，原主密钥单独保管；候选验证后才在维护窗口切换唯一worker，保留可回滚旧镜像与数据 |

真实来源验收还应核对授权、目标日、重复增量、缓存复验、失败日期重试、单位、公司行动及抽样原始响应。免费和付费来源都不能只凭一次成功宣称长期稳定或完整历史覆盖。

## 验收记录要求

每次交付应记录对应 commit、迁移终点、实际检查命令、通过/失败/跳过数量及跳过原因，再列浏览器实际操作与尚存边界。全套检查之后若追加修正，单列增量回归范围，不把两次重叠的通过数相加成新的全套数量。文档和截图更新不等于已发布新镜像；容器、GitHub Actions和人工发行的结果分别记录。

公开截图使用隔离示例或充分脱敏的页面，说明观察日期和数据状态；不上传私人策略、真实自选、密钥、本机路径、原始供应商数据包或内部验收日志。
