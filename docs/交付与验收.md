# 交付与验收

本页提供可重复执行的检查入口，不把某台机器、某次历史任务的通过数量当成当前版本保证。产品功能见[README](../README.md)，数据覆盖见[实现范围与数据边界](实现范围与数据边界.md)，已有安装更新见[版本升级与回滚](版本升级与回滚.md)。

## 交付内容

源码包括前端、后端、锁定依赖、增量数据库迁移、部署配置、备份/恢复及验证脚本。运行行情、业务数据库、数据源 Key、主密钥、备份、依赖和构建缓存不应包含在源码发布包中。空安装不预置假行情、候选、跟踪或权益。

发布应记录源码 commit、镜像摘要（如实际发布镜像）、构建命令及检查结果。公开报告只保留脱敏后的摘要，不能原样上传本机业务记录、凭据、路径或供应商授权数据。

0.1.13发行源码冻结于`1eb35553e79adfcb0ad42ba88ab7f8c24c624f50`，对应 [v0.1.13标签](https://github.com/DreamerXX0301/ad-market-review/tree/v0.1.13)及[本版Release](https://github.com/DreamerXX0301/ad-market-review/releases/tag/v0.1.13)。schema29结构为61张表、37个索引、1个视图及124个触发器；新增027—029，原迁移SHA保持不变。发行、匿名完整拉取、独立恢复及正式切换分别留证，不覆盖旧标签或沿用旧提交成绩。

该冻结提交的[CI运行](https://github.com/DreamerXX0301/ad-market-review/actions/runs/40699418506)记录147个前端测试文件通过，后端5623项通过、2项跳过；数量来自这一次完整CI，不叠加本地分阶段回归。两项是真实审计快照未导入/未留存时的前置跳过，未计为真实数据通过；具体原因在冻结源码的本地`-rs`复核中确认，不冒称原CI日志给出了这些说明。Linux amd64、arm64镜像及14/14容器检查以本版Release附件为准，不能据此声称任意主机、网络或用户数据均已验收。

本版重点核对行业/概念名称与行点击的不同动作、左右独立滚动和窄屏布局、炸板均值来自本批股票、同日原run复用及修改后失效、热点条件不丢、午评每日名额/全局运行锁、收盘核验的同日与未来隔离、28自然日清理及备份。重复结果读取与首次选股计算分开测量，不把局部缓存或HTTP计时称为浏览器/联网整链的收益。

升级恢复副本核对原有54表事实、DDL、来源和密文，再核对7张新增表及迁移登记。已有午评与收盘回看的必要证据随备份恢复；未采集日期保持空态。合法失败会话和锁不得为验收而清空，显式暂停/取消不自动继续。只有用户明确授权的既有重试或业务操作按原流程执行；升级本身不取数、不重放策略、不伪造午评。

## 离线检查

在仓库根目录安装后端依赖：

```bash
cd backend
uv sync --frozen
.venv/bin/python -B -m pytest tests ../scripts/test_deployment.py ../scripts/test_upgrade.py ../scripts/test_package_release.py ../scripts/test_publish_image.py -q
```

测试包含规则三态、日/周/月周期、历史事件、板块与个股隔离、指标和缺口、来源归一化、跟踪生命周期、回测账本、任务、备份恢复等。本轮还覆盖批量筛选后入池的断点与幂等、自选基准冻结、划线价基准和逐日提醒、人工上市身份审计、缺口诊断及来源核验的任务隔离。依赖真实已留存数据的用例可能按前置条件跳过；必须同时查看通过、失败和跳过原因，不能把跳过算验收成功。

在仓库根目录核对公开 schema 导出：

```bash
backend/.venv/bin/python scripts/export_schema.py --check
```

该命令在临时数据库应用全部迁移，只比较结构，不读取或升级现用业务库。新增迁移的升级测试还应证明旧行保留、新表不预置用户记录。

前端检查，在 `frontend/`：

```bash
npm ci
npm run format:check
npm run build
find src -name '*.test.mjs' -print0 | xargs -0 -n 1 node
```

`build` 包含 TypeScript 检查。辅助用例验证排序与 null、日期隔离、周期标签、规则/政策往返、历史事件绑定、搜索类型、图表偏好、五项摘要、自选和任务进度；不代表浏览器真实点击与视觉布局已验证。

## 已初始化实例检查与GET副作用

先按[部署文档](部署与运维.md)启动待验实例；选择自己的隔离候选数据，而不是未经备份升级现用库。完整性检查在 `backend/` 执行，使模块路径与启动方式一致：

```bash
cd backend
.venv/bin/python -m app.cli validate
```

它检查 SQLite 完整性/外键、已发布 manifest 和产物 SHA；只在明确的目标数据目录上运行。它不证明供应商历史全齐，不会补拉缺失日期。

完整前端GET契约审计须对已初始化的隔离副本执行，在 `frontend/`：

```bash
SHIXU_API_BASE=http://127.0.0.1:8789/api/v1 npm run check:api
```

脚本默认地址仍为 `http://127.0.0.1:8788/api/v1`，执行时显式指定候选的完整前缀；上例8789只是独立候选端口示例。不要直接对唯一正式库运行完整套件。

该脚本只发GET，不配置来源、创建同步或执行策略；但读取 `/research/jobs/{identifier}` 会更新报告的 `last_accessed_at_ms/expires_at_ms` 及对应 `retention_pin`，所以不能称为业务库完全不变的只读审计。研究列表轮询不续期。要求目标已有真实初始化数据，空库不能替代这项验收。

正式升级的只读核验应先列明允许访问的接口，排除报告详情等有业务副作用的读取，不运行研究或策略，并在前后核对业务记录与发布目录。读取已有业务资料和运行完整功能审计分开记录；不能把TTL变化笼统豁免成“无数据变化”。完整审计报告写入 `frontend/api-contract-checks.json`，实际日期、计数与脱敏状态需人工复核，不直接携带个人业务内容发布。

## 隔离 Docker 验收

需要 Docker 与 Compose。以下命令从仓库根目录构建本次待验源码；不是现用实例升级命令：

```bash
docker build -f deploy/Dockerfile -t shixu-workbench:validation .
backend/.venv/bin/python scripts/validate_container.py --image-tag validation --report container-validation.json
```

脚本建立唯一的新 Compose 项目、空数据卷和临时测试主密钥，核对健康接口、前端托管、空库无假候选、SQLite 版本、非 root、只读发布卷、API/worker 共享边界、业务写入、备份与新项目恢复。结束只清理自己的容器和卷，不挂现用数据或来源凭据。

容器测试不请求供应商，不能替代真实初始化、跨日增量或来源权限验收。脚本摘要与最终镜像应对应同一源码及前端构建；源码变化后不得沿用旧镜像通过记录。

## 验收记录要求

每次交付应记录对应 commit、迁移终点、实际检查命令、通过/失败/跳过数量及跳过原因，再列浏览器实际操作与尚存边界。全套检查之后若追加修正，单列增量回归范围，不把两次重叠的通过数相加成新的全套数量。文档和截图更新不等于已发布新镜像；容器、GitHub Actions和人工发行的结果分别记录。

性能记录须列接口/页面、观察日、样本次数、首测/预热、缓存和运行环境。首次请求不清缓存时不能称冷启动，HTTP耗时不能代替页面绘制；有界批量读取断言不等于全市场压力测试，策略列表耗时不证明实际选股速度。慢项与未验证范围照实保留，不沿用旧提交耗时宣称新版已提速。

公开截图使用隔离示例或充分脱敏的页面，说明观察日期和数据状态；不上传私人策略、真实自选、密钥、本机路径、原始供应商数据包或内部验收日志。
