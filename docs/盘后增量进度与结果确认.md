# 盘后增量进度与结果确认

在数据中心点击“开始盘后增量”后，工作台立即显示进度窗口。背景导航、搜索、图表、表单和快捷键焦点暂时不可操作；点击背景或按 Escape 不会关闭窗口。任务结束后，查看结果并点击“确认结果，继续使用”解除锁定。

窗口展示开始时间、已耗时、当前任务及实际阶段进度、已排队任务的状态。新盘后增量先完成本次主行情、板块尾部及盘面补充的发布核验，再按原设置执行本地选股、跟踪核对，最后接续划线提醒；上市身份核验可以提前排队，但不能代替后续数据发布。不能只看到主行情100%便当作整个增量结束，后续任务尚未排队或计算尚未安全退出时仍保持锁定。旧冻结任务保持原范围，任务数按实际排队增加。

至少已有3次同数据链的完整历史增量，才显示预计剩余时间范围；否则显示“历史样本不足”。取最近最多12次已完成增量的耗时，包含排队和后续阶段。网络情况、补缺范围和已有队列会改变耗时；超过历史参考区间后显示待估计，不让倒计时归零冒充完成。时间超过60秒按分秒显示。

刷新页面、新标签页或清空浏览器存储后，会从服务端恢复当前未确认增量，不重新提交；同源标签页也跟随阻塞状态。关闭浏览器不会取消服务端任务。断网或后端暂时不可用时保留上次已知状态并允许重新读取，不标记完成。请求尚未接收时，可点击“核查并关闭未接收请求”，由服务端事务证明未创建并封住迟到提交后退出；不会按404或等待时长直接解锁。已有任务记录真实缺失时仍保留未知，需核查存档。

部分完成会明确保留来源缺口；失败、暂停、取消、后续任务排队受阻也显示各自结果并允许确认退出。为防误触，盘后增量、盘前竞价、午评及增量后续步骤不再提供暂停/取消按钮，对应HTTP入口也拒绝停止。此前已存在的停止记录仍保留，真实执行未释放前不能确认。暂停或取消的任务不会自行继续，手动恢复时重新锁定。进度恢复绝不发起恢复、重试或新的数据采集。

只手动处理一个失败/暂停步骤时，窗口明确显示“本次重试步骤”，原失败保留为“历史尝试”，本次结果仅包含所选步骤和其已授权后续分支。它不会代表原整条增量成功，也不会顺便恢复此前已停止的其它阶段。

锁定由服务端会话统一约束：新页面、直接业务接口、策略单次/批量排队均不能绕过；任务进度、结果确认及健康检查仍可访问。已在锁定前接收的读请求可以完成；已有任务不被强杀，增量按原唯一worker规则排队。主行情完成后等待已冻结的后续阶段，核验、发布和滚动清理仍属于本次更新，不能在阶段之间先解锁。

服务端确认解锁后，页面只重新读取曾因本次锁定而失败的GET；已正常读取的隐藏页不整页刷新，已保存选股结果只恢复GET。不会替用户重新执行选股、重发POST或新增取数。

同步后选股沿用每个策略原有的两个设置：“同步完成后重新筛选”保存当日运行结果，“命中新股自动加入此策略跟踪池”决定是否再加入跟踪，后者须与前者同时开启。不勾选入池也可只筛选。数据来源partial不自动补零，具体依赖不足的股票或条件显示待核验；整日本次目标日来源池未发布、代际不符或SHA损坏时，后置计算阻断并说明原因。失败结果不会自动反复重试，已暂停或取消不因重启继续。

接口及状态边界见[手动增量进度契约](../contracts/sync-session-api.md)。数据与文件版本的关系见[数据库与数据流](数据库与数据流.md)。

## 稳定展示与重复提交

阻塞期间暂停背景页面、个股和板块弹窗的业务读取；遮罩使用不透明背景，避免图表重绘透出。接受task_id及epoch不再清掉同一请求已取得的进度；确认前发出的迟到会话发现响应不能重新弹出已关闭窗口。后台任务状态仍由服务端锁核验，不能因隐藏背景而提前解锁。

本日主行情已发布（含发布后保留缺口的partial、no_change）后，禁用重复增量，缺口使用补充或原失败步骤处理。新主任务冻结北京时间盘后日期，不以昨日行情日锁住下一日。盘面补充按行情代际、目标日、年内/板块/最近日期范围核验，完整成功才禁止相同或更小范围重复提交；partial、失败和扩大范围仍可手动修补，独立离线重验与核验计划不被整体按钮拦住。按钮和短事务内创建守卫同时生效，同请求标识仍幂等。新行情日或新代际会重新判断。

## 策略实际执行进度

定时与手动增量均显示本次关联的策略子任务名称、运行状态和实际进度，避免策略正在计算时仍写“等待后续任务排队”。原任务详情保留逐策略命中、待核验、新入池及跟踪核对结果；同日其它手动策略不会按日期误拼入增量。原回执只有部分执行时按实际展示，不凭空补齐。默认突出当前阶段、耗时和预计剩余时间，完整阶段列表可展开。

任务记录可通过 `#data?task=任务ID` 定位一条原记录，显式定位时不自动跳到它的后续步骤。预览版与正式运行版本分离，预览禁止全部写操作。
