# 补充数据对象复用

主行情、盘面补充和业务SQLite分别存储。此文仅描述 `published/market-supplement`，不把板块完整K线、业务库或备份混入同一个容量口径。

## 原有数据与新的写入

原有 `market-supplement-v1` 索引包含逐日完整记录。新发布仍保留同一业务版本，但增加 `storage_version=supplement-index-v2`：索引中各日只保存 `{record_ref,sha256}`，指向不可变 `artifacts/<内容摘要>.json`。既有 `raw/artifacts/accepted/indexes` 命名空间继续使用，旧索引不被改写。

日期记录中的大数组或对象（规范JSON至少2048字节）再独立保存为内容对象，记录通过 `__supplement_fields_v1` 引用它们。这样重新核验时，即使校验日期、上下文或证券档案签名改变，未变化的报价/事件列表仍然共用，不重新复制整批股票数据。原始响应与其SHA保留，不把重新验收等同于当时已经可知。

发布顺序是先写不可变对象、逐个核验，再写轻量索引，最后检查任务状态并原子切换 `head.json`。暂停、取消或失败不能激活半套索引。来源修订创建新对象，历史索引继续指向原内容。

## 读取与备份

`load_supplement(snapshot_id, dates=None, fields=None)` 兼容旧完整索引和新轻量索引。返回业务文档保持相同值与类型，不把存储引用暴露成事件数据。热点筛选只加载近期日期和所需来源池；不展开所有年度和资金资料。缺失、损坏、SHA冲突或非法引用保持unknown，不能当成真实空集。

对象读取只允许固定目录下的64位摘要JSON，拒绝越界和符号链接；单对象32MiB、每索引4096个日期对象、每记录64个大字段。进程内只缓存已核验对象，有1024项/32MiB边界；键包含实际文件身份与修改信息，每次展开返回独立副本，字段对象损坏不会被父记录缓存遮蔽。

### 按能力读取的0.1.9改动

此节描述0.1.9的读取优化；既有正式实例须完成独立恢复验收与版本切换后才包含这些改动。盘面和策略按实际依赖选择补充字段，保留全部留存日期和完整来源池：

| 读取入口 | 展开的补充能力 |
| --- | --- |
| 盘面总览、市场情绪、涨幅榜、涨停梯队、异动监管、板块成员 | 公开涨停细节、年度涨停池、年度跌停池 |
| 行业与题材 | 上述三类池及板块指数历史 |
| 资金与轮动 | 全部五类，包含资金流和板块指数回退 |
| 策略、跟踪与回测的涨停条件证明 | 三类池的全部日期 |
| 未指定范围的内部 `panel()` | 保留原完整读取，兼容已有调用 |

日期不能一律裁成当日、昨日或当前自然年：滚动一年条件可能跨年且排除观察日，历史事件和多日跟踪共用来源证明；最近事件、梯队可看日期和年内覆盖也需要历史。资金来源的较晚采集锚点内还可能包含所选历史日，不能只按对象锚点裁掉它。

每个入口只核验它实际消费的能力。公共索引或选中对象及嵌套字段引用损坏时保持未知；未被依赖的资金或板块历史损坏，不清空已核验的涨跌停证明。这是能力故障隔离的调整，不能将这些故障场景声称为与旧整包读取完全相同。所选对象仍沿用原SHA、路径及文件身份守卫，投影指纹包含范围；不减少证券行、完整分页、原始代码、隔离项或同日反向池证明。

本轮不新增持久汇总库或业务结果缓存。年度统计、JSON展开和序列化分别测量，只有实际耗时证明需要时再增加派生摘要；题材修订、跟踪政策、划线与自选仍按各自原读取路径获取。

### 来源状态的候选投影

同一未发行候选中的来源状态读取使用 `load_supplement_status`。它保留已发布年度覆盖摘要，只展开状态所需的当前日公开池、资金的日期/条目/完整标记，以及核验板块报价所需的完整来源记录。历史数组及当前资金的历史明细不再为状态展示反复展开；旧完整索引继续兼容，公开返回字段和值不变。

此入口与上面的按能力读取不同：状态仍验证完整索引的全部日期对象和嵌套字段引用，任何历史对象缺失、损坏、非法引用或符号链接仍按原整包读取返回unknown。进程内另设最多8192项、按序列化体积计4MiB的引用形状缓存，单项至多64KiB；它只保留对象字段名与引用，不保留行情数组，这不是Python实际内存的硬上限。每次命中仍检查路径、来源SHA和设备、inode、大小、纳秒修改/变更时间，不使用TTL；文件替换、原地修改和发布head变化均重新验证。当前展示使用的记录仍经过原来源校验，不将已缓存摘要当作数据完整证明。

来源列表同时在SQLite中筛选当前凭据修订对应的每项最新核验，只解码返回记录。访问配置页不联网、不解密Key；配置变更与新核验记录下一次读取即可生效，无权限结果缓存。此优化不改精确磁盘统计，也不迁移或改写旧补充对象。

标准备份验证新旧索引及每层字段引用的SHA闭包，恢复到独立目录后不依赖原安装路径。备份仍保留旧索引和被引用原始证据；本改造不会擅自删除旧索引、raw或历史记录。

## 容量与性能验收

需要分别计量首次转换、下一真实交易日新增对象、索引大小、按日期读取耗时和原始证据。不能只展示索引缩小就声称全部补充数据只剩几百KB。独立回放必须将展开后的完整业务文档与旧索引精确对账，并覆盖旧索引兼容、跨版本复用、修订保留、字段缓存损坏、选择日期读取和备份引用缺失。

历史来源修订频率、年度覆盖和用户保留的证据会影响后续增长；本方式减少重复数据，不承诺目录永不增长。整体边界见[存储与盘后增量优化](存储与盘后增量优化.md)。
