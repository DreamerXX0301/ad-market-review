# AI研究与复盘使用说明

当前说明对应 0.1.26 源码、`ai-agent-round-v5` 与 schema40。完整执行链路和技术决策见[AI对话执行流程](AI对话执行流程.md)及[架构与试点设计](AI模型接入与研究试点设计.md)。

## 从哪里开始

1. 完整安装可在「数据源 → AI模型」配置 DeepSeek 或 OpenAI 的 Key 与模型，保存后主动验证，再手动启用。Key 留空保留旧值，清除用专门操作。验证会发送可能收费的极小请求。
2. 从导航进入独立「AI助手」，或在盘面及个股研究页点击「问AI」。盘面总览、盘前竞价、盘中观察、午评和收盘复盘带入观察日与对应时点的问题。选中个股后进入会带入公司名、证券代码和研究问题，有已保存报告时也会带入报告范围。
3. 直接输入问题，也可编辑快捷入口预填的问题。点击发送后才开始生成，所有入口共用同一工作台和历史对话。
4. 继续追问，也可明确切换股票、日期或股票研究话题。换服务、模型或Key代际时开始新会话，旧记录保留可读。

盘面总览顶部的「AI 完整复盘」使用所选日期。系统汇集当日指数与量能、市场情绪、竞价、各档盘中观察、午评、收盘、行业与概念、涨停梯队、消息与事件、龙虎榜、30 日涨幅榜及异动与监管。完整复盘应展开当日涨跌分布、昨日强势股反馈、封板与炸板对照、炸板集中方向、梯队结构与代表股，并串起主要板块从竞价到收盘的变化。每栏以已核验资料和有界样本为依据，缺失时明确说明；监管以所选日留存为准，未来日程按当时已知安排解读。

完整复盘给模型更多时间和正文空间。若超时或达到输出上限，界面会显示原因，已生成的片段标为未完成。可在原会话发送「请重新详细做一次这个交易日的完整复盘」再次读取，也可重新从盘面总览发起；系统不会自动补发付费请求。

宽屏左侧历史、右侧对话；窄屏历史可折叠。输入框固定在对话区底部，模型切换及设置在输入框下方。首问和追问共用相同的流式Markdown排版，支持标题、列表、表格及核验后的来源链接。

回复正文沿用盘面的颜色。涨幅、封板和放量标红，跌幅和缩量标绿，炸板和开板用琥珀色。流式输出与历史回复均适用，零值、普通数字和代码文字保留常规颜色。

## 图片和文件怎样发送

输入框左侧回形针可选文件，也可拖入文件或粘贴图片。支持PNG/JPEG/WebP、PDF、DOCX及UTF-8 TXT/Markdown/CSV/TSV/JSON；每次最多3个、单个5MiB、合计10MiB，每会话累计20MiB。文件名、大小和删除按钮显示在输入框上方，发送失败保留草稿；开始新对话会清空草稿。

图片需选用已支持看图的OpenAI模型；DeepSeek可读文字文件及PDF/DOCX正文。PDF最多20页、附件提取文字本轮合计24KiB。PDF/DOCX内的图表和扫描件不会自动识别，请把需要分析的页面作为图片上传。过大、加密、损坏或没有正文的文件会在发送前明确提示，不会假装已经阅读。

发送后附件与会话一起保存在本机，历史中可查看原附件；删除/到期随会话清理。最近上下文容量有限，超出窗口或附件总量的旧文件不会无限带入，追问较早的文件可重新上传。附件可能增加模型用量，图片每次请求有独立保守费用预留；不需要再次点击验证或自动切换其他模型。

## 可以怎样问

| 研究目的 | 问法示例 | 依据与边界 |
| --- | --- | --- |
| 盘面复盘 | 今天行情有哪些变化？和前一个交易日有什么区别？ | 读指定日已保存盘面，不拿旧日冒充今天 |
| 竞价与午评 | 今天早盘竞价和午间哪些方向突出？ | 分别读真实时点及样本；未到时点和未采集分开 |
| 盘中过程 | 从开盘观察到尾盘，哪些方向延续、走弱或有新封板？ | 读所选日计划内已存盘中快照及严格相邻时点变化；缺档不借竞价或后来数据补齐 |
| 龙虎榜与监管 | 这只股票当天有哪些已存席位披露或监管监控标签？ | 区分单日/三日榜和供应商监控；标签不能当作官方监管函或解除日期 |
| 涨停梯队 | 最高连板是谁？首板有多少？ | 读梯队具体名称、代码和确认数量；缺档可能只有下界 |
| 近期走势 | 宏昌电子最近走势如何？量价配合和板块表现怎样？ | 优先读已发布的同股K线，默认30根日线，区分未收盘与缺少个股分时 |
| 个股价量 | 这只股票这一天成交了多少？ | 核实证券与完成日报价，不要求先生成深度报告 |
| 公司深度研究 | 全面研究这家公司，看看主营、业绩、现金流、估值和风险 | 优先读同股已保存研究，按证据拆业务、行业、业绩、现金流、估值和风险 |
| 财务质量 | 营收和利润变化，经营现金流跟得上吗？ | 核对同口径报告期，区分经营、投资和筹资现金流 |
| 股东与行业 | 行业处在什么阶段？最近披露的股东户数有何变化？ | 周期需要供需指标或同业披露，户数使用实际披露日期及统计期 |
| 强势股分布 | 近30日涨幅前1000集中在哪些题材？这些题材有哪些股票？ | 与涨幅榜同一固定样本，按分类名称查相关股票，或按已核验分类身份精确续查 |
| 次日观察 | 明天应该关注什么方向？需要验证哪些条件？ | 用已经发生的盘面给观察重点、成立和失效条件，不虚构明日报价 |

助手定位是A股行情复盘与上市公司研究。正常股票问法不必反复加“A股”或命中固定关键词；明确生活、购物、编程等话题不展开。资料不足应说明具体缺口，不能用固定的领域拒答代替查询。

盘面概览按观察日读取已发布来源，部分明细复用已核验的派生缓存。缓存缺失、到期或校验失败时，重新从同一观察日的真实来源取得材料。来源也缺档时，继续保留观察日和缺口原因。

## 一轮对话内部怎样执行

首个模型请求只做一次`plan_stock_task`语义计划：理解完整问题、必要的最近真实用户上下文、日期与证券身份，并提出所需资料。程序整体核验真实引用、参数、已声明能力和执行上限，通过并保存计划后才读取资料。页面锚点、旧助手或网页正文不构成新授权。

之后模型依据真实工具结果自然流式回答，普通资料问答通常需要2至3次模型请求；概念或招呼也先计划再回答，可能需要2次。域外或需澄清计划不读取业务资料、不搜索，简短引导仍可能产生模型费用。语义识别合并在原首轮工具规划中，没有另起分类模型；参数符合schema不等于语义绝对正确或所有数字已自动验真。

本地开放八项只读能力：

| 工具 | 用途 |
| --- | --- |
| `read_market_data` | 盘面概览、竞价、午评累计、全天收盘累计与已有资金来源对照 |
| `read_intraday_data` | 所选日计划内盘中摘要，或指定时点的方向、股票样本及封炸跌停变化 |
| `check_data_availability` | 指定日记录、已核验日历与实际观察阶段，不采集 |
| `read_stock_quote` | 核实证券后读取指定完成日个股价量、成交额 |
| `read_stock_trend` | 日周月K线、量价与技术指标，及已核验收盘涨跌停和板块对照 |
| `read_limit_up_data` | 涨停、首板、各连板高度及最高板名单 |
| `read_market_detail` | 指数、行业概念、情绪、30日涨幅榜、竞价/午评明细、龙虎榜、监管与炸板等现有事实 |
| `read_stock_research` | 按完整代码、六位代码或准确证券名读取已保存且未过期的同股研究及符合条件的旧材料；名称和六位代码仅经本地名录精确消歧，未命中或重名时说明身份缺口，不猜代码或借用页面其他股票 |

每问最多3次模型请求，本地最多3次实质读取与2次可用性检查、总计5次，搜索最多1次。工具结果可以批量提出、顺序执行，不是每个工具都必须增加一个模型HTTP。合法超额项记为“本轮未读取”，用已有结果回答，不增加第4次模型请求或自动付费重试。

## 午评、盘中与收盘怎样串联

从盘前竞价、盘中各档、午评或收盘复盘打开 AI，输入框会带上所选日期、时点和分析问题。预填问题限定本地数据，缺档会说明。也可直接在 AI 助手里按日期和时点提问。

`read_intraday_data` 的 `all` 按所选日计划顺序返回摘要，也可指定 `0935`、`0945` 等时点键。当前计划包含09:35、09:45、10:00、10:30、11:00、13:30、14:00、14:30。09:45解读串联竞价、09:35及本档已核验数据。旧日期按原留存回看，未安排的09:45不显示为漏采。相邻变化要求原日期、原版本和两份原始证据均可核验，缺档时保留未知。

`read_market_data(section=noon)`自动串联同一天竞价、截至这份午评实际采集结束时点（cutoff）已完成留存的全部上午盘中快照，以及午评本体。它不会读取下午或收盘正文，也不会把午评之后才补存的上午记录当作当时已知。旧午评缺少盘中档时仍保留缺失。

`read_market_data(section=close)`按原正式收盘锚点串联同日竞价、全部已存盘中、午评和正式收盘封板/炸板等证据，原午间至收盘交集回看另保留口径。收盘观察截止与正式发布时间分别记录；截止后才完成的盘中档、后续日期和当前最新代际不能回填当天过程。缺少可核验的正式收盘锚点时，全天串联明确未知。

各段沿用所选来源的原正文、身份、日期、SHA和AI处理权限，逐轮复核。股票行业/题材、上市板块、跌停状态和炸板回封只在原来源有证据时展示；方向广度、炸板数量缺失会保留原因。板况变化的分类分布按完整已核验差集统计，不能用返回的少量股票当分母。原快照未保存的30日/年内收益、最近涨停或年内次数保持不可用，不用当前历史补称当时已有。

## 明细查询怎样保留范围

`read_market_detail`的`auction`、`noon`先在所选日完整已留存来源内匹配股票或方向，再返回有界名单，不要求当天已收盘。分类和成员必须能对应原时点证据；没有原成员证明时，独立价格仍可保留，归属保持未知。

`dragon_tiger`分别保留单日、三日股票榜、机构榜和游资榜。名称或代码唯一精确命中股票时，才附对应已存席位；匿名席位不合并为某个账户，区间金额不相加。`abnormal`保留请求日期、监控观察日、报价日期、来源标签与期限字段；供应商监控区间不能当作官方监管期限，缺少官方解除日期不推算。

明细关键词查询在完整已载入来源中先过滤再截取，返回已观察数、可确认总数、完整性和省略量。“完整已留存来源”不等于全市场或全部官方记录；来源本身不完整、未命中或数量未知时，不据此声称没有对应事件。

## 前1000题材与行业Top5

「30日涨幅榜」上方显示紧凑分布，默认题材Top5，可切换行业Top5。统计样本在表格前N、搜索、重排和分页之前，按所选日原始近30个市场交易日收益排名取前1000只。不足1000只时，以实际可排名证券数为分母。表格筛选不会改变这份分布。AI 复用同一固定样本与统计规则，涨幅榜和炸板结构页面上单独标注的“最新行业概念参考”只供浏览，AI 仍按观察日可核验的归属作答。

题材维度为经济、政策和产业研究主题。仅排除已审定的`source=fuyao`、`kind=concept`且名称完全等于“融资融券”“沪股通”“深股通”的交易资格属性；原列表标签不删除，行业统计不变。人工同名、其它未审来源同名及仅部分包含这些词的主题仍保留。

同股同分类只计一次，多分类可以重叠，百分比合计可能超过100%。研究题材已知、仅资格标签和未知分别统计；缺归属不填标签，不能用“100%减Top5”猜其他。当前日重新读有效归属，历史日只读当时已有留存，不用当前成员或人工修改倒填历史。

问“30涨幅榜里面有没有电池相关的票”时，AI可以在原前1000里查询留存分类名称含“电池”的行业和题材，合并去重后说明实际命中分类、观察到多少只、返回多少只。继续问某一分类的股票时，使用真实 `topic_id` 等值查询同一样本。缺少分类或成员证据时会说明未知，成员完整且在样本中确无交集时才确认零只。匹配分类名称描述的是已存标签，不能据此断言公司经营、资金净流向或上涨原因。详见[分布契约](../contracts/gainers-distribution-v1.md)。

## 模型配置与自动联网

首次打开对话时，如果还没有配置可用模型，输入框上方会提示当前状态，并提供「前往模型设置」。可以先编辑问题，再前往「数据源 → AI 推理服务」配置、验证和启用模型。返回对话后仍可继续编辑草稿，也可以先查看已有会话。

DeepSeek保留现有Flash、Pro及配置兼容。OpenAI只提供以下八项常用模型，顺序固定，不将账号返回的完整发现目录扩充进选择器，不提供自定义GPT标识：

| 名称 | 模型ID |
| --- | --- |
| GPT-6.1 Sol | `gpt-6.1-sol` |
| GPT-6 Astra | `gpt-6-astra` |
| GPT-6.1 Terra | `gpt-6.1-terra` |
| GPT-6 Sol | `gpt-6-sol` |
| GPT-6 Luna | `gpt-6-luna` |
| GPT-5.6 Sol | `gpt-5.6-sol` |
| GPT-5.6 Terra | `gpt-5.6-terra` |
| GPT-5.6 Luna | `gpt-5.6-luna` |

预置名称不证明账号权限或效果等级。更换Key、模型或验证条件后重新验证，再手动启用；不能借用另一模型的验证结果。旧配置中的其它GPT标识和历史不自动替换，可停用或清Key；新增配置须选支持列表。[模型与核价契约](../contracts/ai-openai-models-v1.md)记录价格版本和官方来源。

应用内原生搜索目前只接通`gpt-6.1-sol`；其它模型可配置不等于已接通联网。模型按需要申请一次受限搜索，不静默换服务或Key。来源限交易所、巨潮及登记的正规财经数据/新闻子域，不开放任意抓站、股吧或自媒体。

用户明确要本系统统计时，网页不能替代内部排名。当前补查资料与历史当时已知分开；网页发布日期未知不以查询时间代填。原生引用证明来源关联，不证明每个数字都已核实。

## 日期、缺口与资金口径

`today`按执行时北京时间解释，旧会话的观察日不会永久变成“今天”。经严格ISO日期核验的观察日可帮助“这一天”等指代，只作查询上下文，不授予领域权限。“明天”也不等于已经核验开市的下一交易日。

| 状态 | 应理解为 |
| --- | --- |
| 尚未到时点 | 竞价结束09:25、午间11:30或收盘15:00尚未到 |
| 已到但未采集 | 时点已到，没有保存对应记录 |
| 未知 | 日历、来源或资料不足，不猜休市或填零 |
| 已核验休市 | 有真实日历支持，不能仅凭星期几或缺行情判断 |
| 本轮未读取 | 这次没有执行该查询，不等于数据不存在 |

自动竞价09:25:30起触发，与09:25观察阈值不同。初始化目标近五年不代表每个日内时点都有五年记录，实际覆盖以实例和所选日为准。`overview`优先完成日盘面，没有完成日行情时可附最新已存时点摘要并注明阶段。候选样本不代表全市场，成交额增量不是净流入，没有真实连续时序就不推造资金轮转或机构账户行为。

## 流式阅读、停止与历史

输出时自动跟随新内容；上翻后暂停，可点「回到最新」或手动到底恢复。Markdown不执行模型HTML或任意图表代码，来源链接在最终核验后展示。

断线重连只续读已有流，刷新可恢复已保存的正文。离开页面后任务继续运行。停止或超时时，已生成的片段会保留并标明未完成，重开历史对话仍可看到原因。超时后可核对用量并手动重试。回答是否完成、来源是否通过核验、费用是否结清分别记录。

同一浏览器、同源页面打开同一会话时，任一标签页提交问题，其他标签页会读取同一个进行中任务并接收回答。若同时发送，先受理的问题继续执行，另一页的草稿保留，待任务结束后可手动发送。停止、删除及模型配置变更会触发其他标签页重新读取状态。重新聚焦页面时也会核对，可见页面每10秒补查一次，覆盖其他浏览器中的变更。会话被删除或到期后，当前草稿可以用于新对话。同一实例的标签页共用会话、设置和预算，标签页间没有账户隔离。

历史默认保存30天，主动创建、发送或完成更新期限，浏览不续期；手动保留可免普通到期。最多200会话，每会话40条消息，用户和AI各计一条。回答阶段仅带最近最多4条已完成消息、合计8KiB，没有跨会话向量记忆。个股研究缓存仍7天，AI只读不续期。

终态流事件15分钟后可回收，最终消息另存。删除/到期移除正文、来源和流，任务与费用审计独立保留，目前没有自动TTL，也不自动VACUUM。重要聊天应手动保留；删除不退次数或抹掉费用。

## 成本、凭据与恢复

安装默认两家合计每天0.50美元、20次模型请求、45秒超时，实际配置以实例为准。次数按实际模型子请求和验证尝试，不按问题数；准入还计排队/在途预留。未知usage、取消、中断或搜索内容计费不明时可能保持待核，本地估算不等于供应商余额或账单。

本地工具结果最多24KiB，模型文字输入96KiB（图片传输另有有界上限）；这不是底层磁盘读取量。盘中每档汇总最多3KiB，单档详情最多10KiB。密集午评/全天累计优先省略可选样本并标明数量，必要时用`phase_fact_columns`共享列名的紧凑结构保留全部必要阶段、原计数、空值及来源引用；不会靠删除尾盘或正式收盘塞进预算。不可再压缩时明确返回容量不足，需缩小查询时点。排队、真实来源核验、模型组织与可选搜索都可能增加等待，流式不代表总耗时消失。

减少无依据回答依靠严格参数、只读工具、日期与SHA核验、确定性统计、容量及缺口标记共同完成，并非只靠提示词。自然语言答案仍没有逐句数值与因果核验，不能承诺零幻觉；重要结论应回看对应来源、时点和统计范围。

Key只提交本机后端密文存储，外置master，不进Git、浏览器持久化、日志或导出。供应商`store:false`不是零日志或零留存保证。标准恢复默认关闭AI、使验证过期，不补发已发送请求；升级在独立版本与恢复副本验证后切换，原历史和账目保留。
