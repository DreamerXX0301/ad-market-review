# 生肖跟踪模块设计

状态：已按本设计接入仓库代码，并在独立测试数据库验收；尚未部署到正式安装。实际接口以 [生肖跟踪 API](../contracts/zodiac-api.md) 为准。

入口位于「自定义研究 → 生肖跟踪」。默认综合表直接显示年内涨幅、30日涨幅、年内涨停及行业概念；支持手动与批量加票、年度切换、编辑理由、重点关注、移出和重新加入。菜单、编辑与详情统一使用模块样式并适配窄屏。

首版的数据边界：市值尚无同日可核验来源时显示未知；跨公司行动的入池收益保持未知；事件区只读现有留存摘要。不会因打开页面自动取数、推荐股票或修改正式库。下文保留完整设计依据；如字段命名与接口示例有差异，以实际API契约为准。

2026-10-30 补充：按用户要求扩展为完整观察工作台。年内涨幅、近30交易日涨幅、年内涨停次数、最近确认涨停日期及行业 / 概念均属于第一版默认字段，不再延后到详情或后续版本。

## 1. 目标与第一版范围

提供一个由用户自己选股、维护理由并持续复查行情的年度观察池。入口命名为「生肖跟踪」，放在「策略跟踪 / 我的自选」附近；无需先创建选股策略。

每个池明确显示两个年份：**2027 年观察 · 2028 猴年**。观察年度是计划标签，目标生肖年度固定为观察年度加一。2026 年的默认池对应 2027 羊年；2027 年默认池对应 2028 猴年；2028 年默认池对应 2029 鸡年。不能把当前公历年的生肖当成跟踪目标。

第一版包含：年度切换、手动搜索和批量加票、关联类型和备注、重点关注、完整行情观察表、行业 / 概念、多组指标、单股详情、移出历史、共用 K 线入口。名单完全由用户维护，不内置推荐股票，不自动发现、加入、迁移或删除成员。指标缺口不导致成员被移出。

自动选股、题材强弱评分、交易建议、收益预测、后台通知、专题收益曲线与独立取数任务不在第一版范围。现有公开行情采集流程继续提供数据。

## 2. 年度切换

- 默认开启「跟随当前年份」，按配置中的 Asia/Shanghai 公历日期选择观察年度，目标年度始终加一。农历春节不是本模块默认切换点。
- 每年 1 月 1 日仅改变默认展示入口。不存在的新年度池显示空态；GET 不落库，首次明确加票时在同一事务创建池和成员。
- 已有年度池保留自己的成员、备注和基准。跨年不结束成员、不归档旧池、不复制名单、不刷新旧基准。用户可以继续查看和维护旧池。
- 手动选某年后切换为「固定年度」，保存这个显示偏好。再次开启跟随时回到当前公历年度。页面跨年重访或重新获得焦点时更新；用户正在编辑时不切走，提交仍绑定打开编辑器时的年度。
- 支持提前选择未来观察年度。例如 2026 年就可以建立「2027 年观察 · 2028 猴年」。实际加入时间和基准仍按当前已发布业务日登记，不伪造 2027 年日期。
- 日期分三项：计划观察年度、目标生肖年度、行情截止日。第一版行情截止日使用独立的当前已发布业务日，不随盘面 view date 改变；不提供用现成员回填历史名单的历史回看。
- 第一版年度入口取整数 1900—2199；生肖按目标年的固定十二年序列计算（2020 对应鼠），这是目标农历年标签，不用于判断某个公历日的生肖归属。

自定义年度切换日期与春节后切换留作后续扩展；第一版固定公历跨年，避免在没有核验农历日历的情况下推算交易窗口。

## 3. 页面与手动加票

页面从上到下为：

1. 页面标题与年度选择：观察年、目标年 / 生肖、跟随当前年份开关。
2. 行情截止日与池状态；主操作「添加股票」，次操作「批量添加」。
3. 「观察中 / 已移出」视图，股票 / 行业 / 概念搜索、关联类型、上市板块、重点关注与数据完整性过滤。
4. 默认综合表：重点、股票 / 代码、当日涨幅、年内涨幅、近30交易日涨幅、年内涨停次数、最近确认涨停日期、行业 / 概念、加入后涨幅、详情与维护操作。
5. 列组「综合 / 涨幅表现 / 涨停活跃 / 量价规模 / 技术趋势 / 跟踪过程」，切换只改变展示列。支持自定义列、显隐、列顺序和密度；默认综合表必须直接包含用户点名的年度表现与行业概念。
6. 单只展开详情：报价与收益、涨停记录、全部行业概念、日周月图表与趋势、加入以来过程、来源与缺口、个人备注和变更历史。

宽屏表格固定股票列，在字段较多时于表内横向滚动，不缩小字体硬塞。窄屏使用卡片，直接显示当日 / 年内 / 30日 / 加入后涨幅、年内涨停与行业概念，其余字段按组展开。股票名称打开共用日 / 周 / 月 K 线，按当前过滤排序后的列表连续浏览。点击代码仅复制完整证券代码。

行业与概念分开：行业显示来源分类名称，概念默认显示前2项并提供「全部 N 项」；生肖关联类型和个人理由是独立列，不能用“地支 / 实际业务”代替证券行业。人工题材有人工标记。成员归属日期与股票行情日分别可查。

全表支持多条件排序，例如先按年内涨停次数、再按近30日涨幅；作用于池内全部过滤结果后分页，不只排序当前页。存在未知 / 下界时单列状态，不能把不完整次数与精确次数混成确定排名。选股筛选与浏览过滤分开，过滤不改变名单、入池基准或生成策略信号。

### 单只添加

「添加股票」内先搜索名称或代码，再从已核验本地 A 股名录选中准确证券。股票身份统一使用 `instrument_id`（含 SH / SZ / BJ），不根据六位数字猜身份，也不接受指数、行业、概念和未核验自由文本。

可填写字段：

| 字段 | 规则 |
| --- | --- |
| 股票 | 必填，选中已解析的证券身份 |
| 关联类型 | 名称直接关联、谐音、地支、文化 / IP、实际业务、自定义；默认自定义 |
| 自定义类型名称 | 自定义时选填，最多 30 字；不另建全局题材 |
| 加入理由 | 选填，最多 1000 字 |
| 依据链接 | 选填，最多 3 个 http/https 链接，不自动抓取；用户录入不冒称已核实 |
| 重点关注 | 默认关闭，只影响显示顺序 |

用户可以加入任何已核验 A 股，不强制名称符合生肖关键词，也不强制填写理由。系统负责真实身份和行情核验，用户负责自己的关联判断。

确认按钮显示完整目标，例如「加入 2027 观察池 · 2028 猴年」。不需要提供买入价或持仓数量；这里保存的是观察基准，不是账户成本。

### 批量添加

粘贴名称或完整代码，以换行、空格、逗号分隔；一次最多 100 项。先预览每项的准确证券、重复项、歧义项与未识别项，用户处理歧义后明确提交有效且勾选的项。提交部分有效项必须在按钮上写明数量，不能静默丢弃错误项。

默认共享关联类型与理由，允许提交前逐项修改。同一个池内已在观察中的股票跳过且返回原记录；不覆盖原理由、重点设置或加入基准。

第一版每池最多 500 个观察中成员。达到上限时整次新增拒绝，重复项不占新增容量。一次提交整体成功或整体回滚，不使用逐股提交形成半成功状态。

## 4. 成员生命周期

- 成员独立于「我的自选」、人工题材、个股策略跟踪和板块跟踪。加票不自动收藏、不改题材、不生成选股运行或策略跟踪轮次。
- 同一股票可以存在于多个年度池，每个池有独立加入基准。
- 编辑理由、关联类型、依据链接或重点标记保留原基准，并追加变更审计。
- 「移出」将本轮记录归入已移出历史，可填写原因。保留进入和结束日期及基准；不删除该股票在其他模块的记录。
- 已移出股票再次添加，创建新一轮成员记录和新基准；旧轮次仍可查。按钮使用「重新加入」，不提供会覆盖旧轮次的隐式恢复。
- 已移出列表的“加入后涨幅”截止到移出业务日，不继续用最新价格漂移；详情可另行打开当前 K 线。缺移出日报价仍显示未知。
- 年度切换本身不触发成员生命周期变化。单只重新加入与跨年新池均不继承旧基准。
- 第一版不提供永久删除池或成员、自动清理和一键迁移旧名单；后续可增加明确预览的复制功能，复制时重新建立基准。

## 5. 行情与统计口径

实际操作时间使用服务端毫秒时间；`added_business_date` 取提交时已发布业务日，界面明确显示“基准行情日”。例如盘中尚未发布当日收盘，基准可能为上一业务日，不能标成实时买入价。

入池基准取该日唯一有效、实际有成交的原始日 K 收盘，冻结定点价格、单位、来源引用、来源 SHA、行情代际、日历和算法版本。基准不可由客户端提供，成功冻结后不可改写。无有效报价仍允许记录观察成员，但价格和收益为 unknown，并保留具体原因。

### 年度、窗口与涨停核验

- “年涨幅”统一命名为“年内涨幅”，“年涨停”统一命名为“年内涨停次数”；年份取**行情截止日所在公历年**。看2027观察 / 2028猴年池且行情截止在2026年时，列头说明仍为2026年内，不能伪造2027 / 2028年度数据。
- 年内涨幅以上年末已核验最后交易日收盘为基准，本月以上月末为基准；不能拿本年 / 本月第一条报价替代。近N日严格使用 T 与 T−N 市场交易日，不替换成最近N条报价，不把本月视作近30日。
- 年内涨停按同年1月1日至行情截止日的已核验收盘涨停事实计数，不等于盘中触板。缺源或身份 / 原价核验不足时显示“已确认≥N次 / 覆盖不足”，完整零才显示0。
- 最近确认日期可以在年度外；用词为“最近已确认涨停”。只有事件之后的必要区间完整，才能确认它是截至观察日的最近一次；精确次数、下界、最近日期完整性独立。
- 每个统计单元有来源、日期、价格口径、覆盖和原因入口；未知不补0，不因某一指标缺失而隐藏整行。

### 跟踪路径与分类口径

加入后最高收盘涨幅使用本轮冻结基准与同口径期间最高收盘比较；当前回撤使用当前收盘 / 本轮期间最高收盘 − 1；期间最大回撤按先出现的收盘峰值到其后收盘谷值计算，不能用整个区间最高 / 最低不分先后拼成最大回撤。基准日为第0日，追踪日数依已核验市场交易日历计算，停牌不补K。

路径区间任何必要报价或公司行动转换缺失时，完整路径指标保持未知，局部已见极值只能以“已观察区间”单列。端点收益可以按既有算法单独判断可比性，并披露中间缺日，不能据此宣称整条路径完整。第一版相对基准默认明确显示上证指数（可在设计实施时扩展选择），取同一开始 / 结束交易日收益差，单位为百分点，不称超额收益率或真实账户回报。

行业、概念按当前目录与人工覆盖读取；来源采集时间、关系有效业务日、行情截止日分别保留。某个概念后来补入时，不把它回填成过去涨停的原因；个股历史涨停可以展示，但不得据当前分类生成“当时所属行业”的历史结论。

第一版加入后涨幅沿用现有自选的保守原价口径：同日有效报价可计算真实 0；跨日须核验公司行动完整性及可比性。期间存在公司行动且缺少已验转换证据时收益未知，不把前复权显示价与冻结原价直接相除。

不把不同加入日起算的个股收益平均成“池收益率”。池概览显示成员 / 重点数、当日上涨 / 下跌 / 平盘 / 未知家数、当日已确认涨停数、当日涨幅中位数与各指标覆盖数；统计全部当前筛选结果并注明样本分母，未核验的成员单列。行业 / 概念分布注明一股可多归属，不累加冒充去重股票总数。排序对全部筛选结果生效，缺值在升降序均排末尾。

缺失基准通过明确的「核验缺失基准」操作，按原基准日读取本地已发布证据后幂等补齐；一次最多 100 条。GET 不进行补写或新任务创建。已成功基准不更新，仍缺失的保留原日期及原因，不能改用补齐当日价格。

### 持续跟踪与变化记录

第一版随已有行情成功发布后读取新一代指标；浏览不会另行开启数据自动计划。列表显示数据更新日期，用户可主动刷新本地已发布结果。个人备注与归属变化每次重新读取，不被行情缓存固化。

单股详情汇集实际已保存的涨停、划线和维护事件。若后续增加“首次放量 / 突破 / 均线失守”等专属每日变化记录，必须另行实现用户主动核对或明确启用的本地盘后核验；保存当时规则版本、日期、来源和三态结果，由唯一worker幂等追加。默认关闭，不为旧冻结任务扩范围，不因看表而自动补跑历史；本文不把专属每日事件台账假称已有能力。

| `zodiac_pool_member` | `id`、`pool_id`、`instrument_id`、`round_no`、状态、类型、理由、依据、重点、加入 / 结束业务日及实际时间、冻结名称 / 价格 / 基准证据、修订号 |
| `zodiac_pool_audit` | 追加式记录创建、加入、编辑、移出、重新加入、基准补齐；含操作者类别、实际时间、关联请求及前后字段 |
| `zodiac_pool_request` | 写操作幂等键、规范参数 SHA、最小响应引用；同键不同参数返回冲突，同键重放返回原操作 |

每个 `(pool_id, instrument_id)` 最多一条观察中记录，使用数据库部分唯一索引保护并发。已结束轮次和成功基准以数据库约束保护不可覆盖；可编辑元数据通过 revision 乐观锁防止丢失更新。

视图偏好使用已有 UI 偏好机制，只保存跟随年份 / 固定年度与过滤项；正式名单和理由不放浏览器存储。所有新增连接沿用 foreign_keys、recursive_triggers、busy_timeout；迁移全成功后才登记版本号，实施时分配实际下一个迁移号，不在设计中抢占。

### 拟议 API（前缀 `/api/v1`）

| 方法与路径 | 行为 |
| --- | --- |
| `GET /zodiac-pools` | 当前北京时间年度建议、已创建年度摘要；只读少量 SQLite，不遍历历史行情 |
| `GET /zodiac-pools/{observation_year}` | 年份、生肖、是否已创建、当前行情截止、成员计数与 revision；未创建返回空池描述 |
| `GET /zodiac-pools/{observation_year}/members` | `status/query/relation_kind/boards/topic_ids/focus/coverage/filter/sort/metric_group/page/page_size`，多条件排序在全量过滤后分页；默认返回综合字段；高级过滤使用白名单，不接受任意表达式 |
| `GET /zodiac-pool-members/{member_id}/metrics` | 按组返回涨幅 / 涨停 / 量价 / 趋势 / 跟踪路径及各组覆盖；相同截止日和代际，已结束成员明确使用结束日 |
| `GET /zodiac-pool-members/{member_id}/evidence` | 分页返回本轮可链接的既有事件、来源日期和保留覆盖，不触发远端取数或研究任务 |
| `POST /zodiac-pools/{observation_year}/members` | `{items, request_key, expected_business_date, expected_generation}`；首次加票原子创建空池与成员，返回 added / already_active / new_round 明细 |
| `PATCH /zodiac-pool-members/{member_id}` | `{revision, relation_kind?, custom_label?, reason?, references?, focus?, request_key}`；只改元数据 |
| `POST /zodiac-pool-members/{member_id}/end` | `{revision, reason?, expected_business_date, expected_generation, request_key}`；结束本轮，保存结束业务日及证据 |
| `GET /zodiac-pool-members/{member_id}/history` | 有界分页审计，用户可以核对何时改了什么 |
| `POST /zodiac-pools/{observation_year}/verify-baselines` | `{member_ids, expected_generation, request_key}`；最多 100 条本地基准重验，不调用供应商 |

成员读取返回 `pool_revision/business_date/snapshot_id/quote_date/stats_year/metrics_as_of` 及 `summary/coverage`，每个统计有 state、reason、起止日和价格口径。核心字段沿用 `return_ytd_pct/change_30d_pct/limit_up_ytd/limit_up_ytd_observed/last_limit_up_date/sessions_since_limit_up/current_topics/current_industries`，不建立另一套含义不同的别名。已移出默认所有行情统计截止结束业务日，当前行业概念若另行提供必须标为当前归属；不能一行混用未标日期的旧收益和最新报价。规范错误为 422；年度、revision、行情业务日或代际发生并发变化为 409。无有效本地业务日时允许浏览空池，但新增返回明确“先发布行情”的原因。

身份检索复用既有标的搜索能力并在服务端限制 A 股。代码、名称及交易所身份由后端复核；不把输入的纯文字直接写成证券。

API 在事务外批量读取固定已发布行情，提交短事务内重验行情 head、业务日、池 / 成员 revision 与容量，再写成员、审计和幂等回执。读数据与写事务不可交错使用不同代际；报价取数不持 SQLite 写锁。

历史价格读取使用既有不可变发布文件和有界缓存，不跨进程打开 worker 正在写的 DuckDB。复用跟踪报价服务时须按精确证券 / 日期有界批读，不能因几个不同加入日期展开全市场全历史。

年内 / 30日 / 涨停字段复用 `topic_member_metrics.member_metrics` 与 `stock_summary.summary_fields` 的批量语义，行业概念复用 `stock_memberships`；禁止列表逐只调用单股 summary 或完整 chart 接口。排序所需池内候选最多500只，分有界批次读取，先得到完整排序字段再分页；技术图表与路径详情按需加载，但若用户选择该指标排序，必须为完整过滤集计算或明确拒绝，不能以当前页值假装全池排名。缓存键包含行情、补充来源指纹、日历、观察日、证券集合与算法版本；归属和个人修改用独立修订失效，不能仅用行情代际长期缓存行业概念。

冻结基准证据需登记在现有引用与标准备份闭包中，保留精确所需来源与 SHA；不为一个基准无条件保留整个全市场代际。备份必须能在独立恢复后还原名单、基准与来源，缺来源不宣称完成核验。

## 7. 实现拆分与验收

前端拟新增 `features/zodiac/`，拆分年度选择、成员列表、添加弹窗与成员编辑；路由 `#zodiac`。图表、代码复制、格式化、股票搜索和行情覆盖提示复用现有组件。

后端拟新增 `routers/zodiac.py`、`services/zodiac_pools.py`、年度和生命周期纯规则，以及一次增量迁移。抽取可复用价格基准规则时保持现有自选契约不变；不让生肖模块依赖或写入策略跟踪表。

实施至少核验：

1. 北京时间 2026→2027 跨年显示羊→猴、2027→2028 显示猴→鸡；固定年度及正在编辑的表单不被切走。
2. 提前建池真实加入日期、观察年度、目标年度互不混淆；GET 未创建年度不写库、不取远端数据。
3. 添加、批量歧义预览、重复 / 并发添加、容量边界、整批回滚、相同请求重放 / 异参数冲突。
4. 修改理由和重点不重置基准；同股跨池隔离；结束后重新加入生成新轮次；跨年不结束旧成员。
5. 已移出收益截止结束日；缺入池 / 当日报价、停牌、公司行动、日历不足均保持未知；实际有成交同日可显示 0。
6. 基准缺失只补原始日期；成功基准不可变；写入期间行情切代返回 409；只读缓存不吞掉最新备注和状态。
7. 所有操作对自选、题材、策略跟踪、板块跟踪、任务和自动计划无副作用。
8. 桌面和窄屏添加 / 编辑 / 移出 / 年份切换可用；键盘可操作；预览示例不作为真实产品种子。
9. 备份独立恢复后核对成员数量、轮次、基准值和证据 SHA；正式升级按版本升级与回滚文档验收，不直接迁移唯一业务库。
10. 默认表格必须直接显示年内涨幅、30日涨幅、年内涨停与行业概念；自定义列和列组不改变数值口径，窄屏仍保留这些核心字段。
11. 年内 / 本月 / 近N日分别对账，统计年份跟随行情截止日而非生肖年度；年内涨停完整0、已确认下界和未知三种展示及排序分别核验。
12. 行业 / 概念搜索与过滤覆盖全部归属，折叠不漏检；多来源和人工归属可追溯，修改后同一行情代际也立即刷新；不回填历史归因。
13. 换手、日量比、市值缺来源为未知；日周月指标有周期与预热证据；跟踪最高收盘涨幅、当前回撤、最大回撤分别核验，缺路径不输出假完整值。
14. 多条件过滤 / 排序在全池执行后分页，逐指标覆盖数与未知家数对账；无逐股远端请求、无N+1全历史扫描、无读取即创建任务。
