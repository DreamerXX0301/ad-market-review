# 部署与运维

冒险的梦想家提供本机源码和 Docker 两种运行方式。API 默认只监听本机，唯一 worker 负责行情写入与任务消费；新安装默认不开自动计划，启动不发起初始化；已显式开启的当日计划由唯一worker在有效窗口检查。已有安装升级先读[版本升级与回滚](版本升级与回滚.md)，不要在现用目录原地拉取并迁移数据库。

本页配合[0.1.15发行说明](../CHANGELOG.md#v0115)，源码以 [v0.1.15 标签](https://github.com/DreamerXX0301/ad-market-review/tree/v0.1.15)为准。安装示例的实际镜像可用性与摘要以[本版 Release](https://github.com/DreamerXX0301/ad-market-review/releases/tag/v0.1.15)、[镜像发行工作流](https://github.com/DreamerXX0301/ad-market-review/actions/workflows/publish-image.yml)及本版 `release-image.json` 为准；其中完整 `git_commit` 应与源码标签、镜像OCI revision一致。推送 `master`、源码CI通过或本地构建成功均不会更新既有GHCR镜像，也不能覆盖 `v0.1.7` 及更早标签。从源码构建时也须在独立目录验证，不把旧版回执作为新增功能已交付的证据。

## 本机首次启动

需要 Node.js 22.12+、npm、uv，以及 Python 3.13–3.14。Python 实际加载的 SQLite 必须为 3.51.3 以上或程序认可的官方修复回移版本；升级 duckdb 包不会升级 Python 的 SQLite。程序启动会检查 SQLite 运行库。

在仓库根目录执行：

```bash
./scripts/dev.sh
```

脚本安装锁定的后端依赖、迁移默认业务库、构建前端，再启动 API 和一个 worker。浏览器访问 <http://127.0.0.1:8788>；Ctrl+C 停止本次启动的进程。它用于首次安装或开发，不用于现用版本的无感升级。依赖已有变更时先在前端运行 `npm ci`。

启动服务可以消费此前已授权的排队任务，或恢复符合条件的中断任务；未开启自动计划时不会自行创建新一天的行情同步；已开启计划只允许当天有效窗口，不跨日补历史。手动初始化 / 增量开始后，冻结计划内的分类、板块、补充及本地提醒检查可自动衔接。显式暂停 / 取消仍由用户决定是否继续，不等于开了每日定时任务。

独立调试：

```bash
cd backend
uv sync --frozen
.venv/bin/python -m app.cli migrate
.venv/bin/python -m app.worker
```

另一个终端在 backend 目录启动 API：

```bash
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8788 --workers 1
```

前端构建需在 frontend 目录执行 `npm ci`、`npm run build`。设置数据源并手动初始化的顺序见 [README](../README.md)。不要对同一 data 目录启动第二个 worker。

## 已有原生安装：电脑重启后启动

本版源码包含`scripts/native_service.py`，也可使用部署者生成的桌面入口。该工具读取私有控制文件指定的已验收独立应用版本，不从当前`master`切换应用、不执行迁移。旧v0.1.13冻结源码未包含此辅助脚本，既有标签与镜像不重写。

已完成独立恢复、验收和切换的原生安装，重启电脑后双击部署时生成的桌面启动入口；它读取当前私有部署控制文件，不绑定旧版本目录。只关闭网页时，已启动的服务仍可运行；不需要再次构建或安装。启动器只启动控制文件已经验收的源码、数据目录和Python环境，自身不迁移、不初始化或创建业务任务。重复点击只核验并复用同一API与唯一worker。

若已明确开启自动计划，worker启动后会在当天有效窗口检查并提交到点任务；这来自既有计划授权，不是启动器自动开启计划。关机无法采集，午评13:00后和跨零点不补历史。原生服务和Docker不能同时使用同一份业务库、published或worker工作目录，避免第二套进程共写；本地与线上各自使用独立数据和配置。

源码运维入口为`scripts/native_service.py`，提供`start`、`status`和`stop`。先进入仓库根目录，用当前控制文件选定的Python运行，例如：

```bash
python3 - <<'BOOT'
import json
import os
from pathlib import Path

control = Path('data/work/runtime/local-service.json').resolve()
settings = json.loads(control.read_text())
python = Path(settings['python_environment']) / 'bin/python'
os.execv(str(python), [str(python), '-B', 'scripts/native_service.py',
                      'start', '--control', str(control)])
BOOT
```

仅查状态时将参数`start`改为`status`，停止时改为`stop`，也可双击部署者生成的桌面“停止冒险的梦想家.command”。停止工具先核验同一部署的API、worker、端口及数据锁，再逐个复核进程身份并发送SIGTERM；API等待请求结束，worker按原有机制完成当前任务后退出，不再进入下一轮消费。最长等待30秒，只有确认进程退出、端口和锁释放后才报告已停止；超时会提示仍在收尾，稍后可再次停止，不强杀、不删除数据、不修改任务或自动计划配置。服务停止期间本地自动计划不会执行；需要使用时再双击启动入口。

只读取私有部署元信息和必要路径，不打印控制文件或读取主密钥正文。控制文件缺失时不要手工猜路径或生成新密钥，先确认已有安装与原密钥位置。此工具是源码运维入口；Docker安装继续用其对应Compose管理，不把原生数据自动挂到新空卷。进程启动时间统一按C语言环境读取，避免Finder与终端语言不同造成误判；旧控制文件若保存了本地化日期，须先在原语言环境核验同一PID、启动时间和完整身份后转换记录，不能直接清空校验字段。

启动时核验冻结源码与前端SHA、迁移小元数据、同源路径、进程身份、端口和worker锁；不会为普通重启扫描全部行情、完整业务表或做全量恢复验收。端口、数据锁或PID属于其他实例时拒绝且不终止它；部分启动失败只收回本次新建进程，保留原本运行的服务。部署切换、启动和停止共用排他锁。显式暂停/取消的任务不会因此继续；此前已授权且仍可消费的排队或中断任务按应用原有规则处理，不代表自动创建每日取数。

## Docker 从源码构建

直接拉取发行镜像的推荐安装方式见 [Docker部署](Docker部署.md)。镜像允许匿名拉取，本仓库源码和公开Release附件也可匿名下载，GitHub CLI为可选工具。以下自行构建命令以已取得对应版本的完整源码为前提：

`deploy/Dockerfile` 使用固定摘要的 Node/Python/uv 镜像、锁定依赖与经 SHA3 校验的 SQLite 源码。当前镜像内要求实际加载 SQLite 3.54.1。支持显式替换镜像来源，但发行记录仍应保留固定摘要。

以下命令只用于全新独立实例，不能用来覆盖已有安装：

```bash
python3 deploy/create_secret.py "$HOME/.local/share/shixu-compose-secret/master.key"
export SHIXU_MASTER_KEY_FILE="$HOME/.local/share/shixu-compose-secret/master.key"
docker compose -p ad-market-review-new -f deploy/compose.yaml config
docker compose -p ad-market-review-new -f deploy/compose.yaml build
docker compose -p ad-market-review-new -f deploy/compose.yaml up -d
```

`deploy/compose.yaml` 是源码开发入口，默认 `up -d` 会启动 API 和唯一 worker；`deploy/docker-compose.yml` 与 `deploy/compose.release.yaml` 则要求显式启用 worker。已有数据的候选预演不能直接套用上面的全新安装命令；按升级文档使用恢复副本，先仅启动候选 API。

源码构建默认使用 `shixu-workbench:local`，`VCS_REF` 默认为 `unknown`。需要交接本地候选镜像时，在干净的已审定提交上构建并传入 `APP_VERSION`、`VCS_REF` 和 `BUILD_DATE`，再记录镜像 ID；这些参数分别来自根 `VERSION`、完整提交 SHA 和该提交时间。只有实际上传仓库并核验后才有可交接的仓库摘要，本地构建不能冒充 GHCR 发行完成。

主密钥父目录必须是 0700；创建脚本拒绝覆盖旧密钥。文件型 Compose secret 以 0444 供非 root 容器读取，宿主其他用户不能遍历其 0700 父目录。不要把密钥正文放进 Git、镜像或环境文件；密文与主密钥必须分开保管。已有密文需原主密钥才能解密。

默认只绑定 `127.0.0.1:8788`；新实例可设置 `SHIXU_HTTP_PORT=8789`。检查与停止：

```bash
docker compose -p ad-market-review-new -f deploy/compose.yaml ps
docker compose -p ad-market-review-new -f deploy/compose.yaml logs --tail 100 api worker
docker compose -p ad-market-review-new -f deploy/compose.yaml down
```

`down` 保留数据卷，日常停止不要加 `-v`。发行用的 `compose.release.yaml` 不构建镜像、要求明确镜像引用，worker 需显式启用；完整步骤见[版本升级与回滚](版本升级与回滚.md)。

## 存储与进程

| 存储        | API                | worker   | 用途                                       |
| ----------- | ------------------ | -------- | ------------------------------------------ |
| business    | 读写               | 读写     | SQLite 业务短事务、WAL 串行写锁            |
| published   | 只读               | 读写     | 不可变行情、快照、manifest、已验收补充证据 |
| credentials | 读写密文           | 只读密文 | 来源凭据，不含主密钥                       |
| work        | 不共享 worker 文件 | 独占读写 | 活动 DuckDB、锁、临时计算                  |
| raw         | 不挂载             | 读写     | 原始下载与重放材料                         |

一次性 init 在新卷中设置权限并迁移，API/worker 以 UID 10001 运行。`/health` 仅代表进程可用，不代表数据完整。API 不得打开另一进程正在写入的 DuckDB。发行配置另给 API 独立 work tmpfs，缓存不跨重启保存。

本机默认数据根为仓库 `data/`。独立版本需显式配置 `SHIXU_DATA_DIR`；必要时同时指定 `SHIXU_SQLITE_PATH`、`SHIXU_PUBLISHED_DIR`、`SHIXU_RAW_DIR`、`SHIXU_WORK_DIR`、`SHIXU_CREDENTIAL_DIR` 与 `SHIXU_CREDENTIAL_MASTER_KEY_FILE`。检查所有覆盖变量，避免副本误连现用库。

### 0.1.9选股 CPU 预算

0.1.9新增有界纯计算进程池。`SHIXU_SELECTION_CPU_WORKERS` 控制每次选股作用域的纯 CPU 子进程上限，省略时为 `4`，允许 `0`、`1`、`2`、`3`、`4`。`0` 完全关闭子进程并沿用串行准备；`1` 至 `4` 按需创建进程，暖缓存不创建。唯一行情 worker 数量、数据源请求量、完整证券范围和规则口径不受此配置影响。

默认 `4` 是固定上限，不会自动按可用 CPU 或内存调整。资源紧张的服务器可先使用 `0` 或 `1`；`1` 仍有进程启动和传输开销，不保证比 `0` 更快。每个子进程的原生计算库线程限制为1，但仍需为父进程、API与唯一行情worker预留内存。不同配置的速度和内存应在相同来源副本上分别核验。

本机在启动0.1.9 API和worker 前向二者注入同一个环境值，例如 `export SHIXU_SELECTION_CPU_WORKERS=2`。Compose 的三份入口均透传此变量，可在相应环境文件中填写 `SHIXU_SELECTION_CPU_WORKERS=2`；[示例环境文件](../deploy/.env.example)提供默认值。已有服务更换环境须按维护流程重启或重建相应服务，不能在运行中直接替换现用版本。

每个最外层选股作用域创建时冻结预算，嵌套调用沿用该预算，运行中改变环境不会改变已开始的任务；代码显式指定的进程数也不能扩大运维上限。非法值（包括空值、负数、小数及超过4）安全降为串行，并记录只含配置名的警告，不输出被拒绝的原值。有效的 `0` 不产生配置错误警告。基础设施不可用时也回到原串行准备，暂停、取消和实际计算错误仍直接传播，不靠重试进程掩盖。

## 本机备份与恢复

备份到尚不存在、且位于数据目录之外的路径：

```bash
backend/.venv/bin/python scripts/backup.py --output backups/before-upgrade
```

备份使用 SQLite Online Backup API，固定已发布不可变文件引用，校验 SHA256，复制业务库、被引用行情和凭据密文。盘面补充包含已验收原始证据与指针；复制期间发生变化会拒绝本次备份。备份时等待补充任务结束，避免同时修改来源凭据。

备份不含主密钥、顶层 raw 下载全集、活动 DuckDB 或可重算工作缓存。manifest 校验完整性，不提供防恶意篡改的数字签名。备份目录仍含个人策略与密文，不应公开。

自选、首次加入基准、水平线、已触发提醒和人工上市身份更正属于SQLite业务记录，随业务库保留；`work/`的本地覆盖/缺口报告及`raw/`的额外来源核验响应不在标准备份中。恢复后可重新运行本地核验；需要长期保存额外来源证据时另做私有归档并核对SHA，不将其上传公开仓库。

恢复必须指定尚不存在的新目录：

```bash
backend/.venv/bin/python scripts/restore.py backups/before-upgrade --target /独立路径/shixu-restored
cd backend
SHIXU_DATA_DIR=/独立路径/shixu-restored .venv/bin/python -m app.cli validate
```

先校验清单、大小、hash、SQLite 完整性再恢复；排队/运行任务会暂停，保留已完成结果、策略、人工变更与发布指针。使用原主密钥或重新配置数据源；不要让新旧进程共写恢复目录。

## Docker 卷备份

脚本使用短命 helper 容器，校验 Compose 项目和卷类型标签。下面镜像标签必须是本机已有且已验证的版本；恢复目标项目必须全新：

```bash
backend/.venv/bin/python scripts/docker_archive.py --image shixu-workbench:local backup --project ad-market-review-new --output backups/docker-before-upgrade
backend/.venv/bin/python scripts/docker_archive.py --image shixu-workbench:local restore backups/docker-before-upgrade --new-project ad-market-review-restored
```

恢复不启动服务、不复制主密钥、不覆盖已有卷。验证后再按照升级文档以对应版本启动。不要运行卷清理或删除唯一旧版备份；异盘留存周期由安装者安排。

## 检查与故障处理

- 先看任务阶段、覆盖原因及 API/worker 日志；记录日期、快照 ID 和错误类型，隐藏凭据与个人策略。
- 显式暂停/取消不会自动继续；恢复备份后由用户决定是否恢复旧任务。来源失败不清空已发布版本，不把缺失标成零。
- 迁移文件只允许新增，不改已执行文件；不要把 schema 导出 SQL 当成业务恢复脚本。
- 复现测试、合成数据检查与独立容器检查见[交付与验收](交付与验收.md)。标准升级计划与恢复边界见[版本升级与回滚](版本升级与回滚.md)。

SQLite/WAL 与活动 DuckDB 应使用本地磁盘；当前没有共享网络盘、断电恢复或零停机双写保证。

## 新增功能验收与版本交接

0.1.15在0.1.14基础上统一自动计划、增加昨日板型与板高浏览，并将新增量的选股、跟踪与提醒后置到本次数据发布之后；同日复用核对实际补充来源。0.1.14升级无新增迁移，仍为schema32、66张表；更早029实例须先按升级路径追加030—032。全部业务事实、迁移SHA、来源及密文须对账。竞价内嵌原件与午评raw/noon进入标准恢复核验，主密钥外置，不复制新Key替代原Key。

新安装自动竞价、午评和盘后计划全部默认关闭。恢复副本关闭已保存自动配置并增加修订号，保留原台账和自定义时间、暂停原排队/运行任务，不自动继承旧实例触发权。候选只启动API；维护窗口最终备份后停止旧worker，再切换同源前端/API和唯一新worker，按用户授权在唯一正式实例重新开启。恢复、迁移和部署不创建新的业务任务。回滚使用对应旧源码与切换前完整备份；即使schema同为32，也不让旧程序直接接管已经使用的新版本目录。更早schema29版本只能使用对应29回滚库。

划线未实际提醒持续监控，首次提醒日为第0日，之后继续60个市场交易日。超过期限仅由新手动盘后增量的授权核验任务清理线与关联提醒，自选、策略跟踪保留；部署不触发清理。连板反馈明细仅昨日二板及以上，首板只计入概览，缺来源保持未知。见[提醒规则](划线提醒到期清理.md)与[板型反馈](连板高度板型与反馈.md)。

使用独立恢复副本中已留存的数据做以下功能验收，不为验收重新初始化或补造示例数据。研究报告详情读取会续期缓存和保留引用，须单列记录；要求业务记录完全不变的只读对账应排除该读取，不把TTL变化当作无业务变化：

- **选股与本地增量计算**：相同冻结来源与规则下，最新两期指标、全部候选及依据与完整输出对账；覆盖缺口、零量、公司行动和完整周/月边界。分层缓存与64交易日技术尾部按冷、暖、参数变更及重启分别验证，首次空缓存及简单阈值场景仍可能更慢。分类结果、跟踪批读及个股资料末端对账原字段和未知状态；增量合并核对全部覆盖字段与写出SHA，板块摘要与原始闭包仍复验。线上来源限速保留，不用本地局部计时宣称在线整链收益，见[日期切换与选股性能](日期切换与选股性能.md)和[存储与盘后增量优化](存储与盘后增量优化.md)。
- **图表与增量会话**：K线右侧标签的单条和全部显隐、日/周/月自适应默认范围及手动缩放保持一致；整链锁在刷新及其它标签页可恢复，阶段结束不提前解锁，实际安全停止或完整结束后按结果确认。暂停、取消不自动继续，浏览不创建新数据任务。
- **市场情绪**：首屏沪深广度温度、阶段、下一交易日计划与页内目录可见；切换盘面日期后不残留上一日计划。日历未知时不猜下一日，缺少报价、覆盖或成交额证据时保留待核验，未来条件均未观察。完整口径及场景见[市场温度与下一交易日计划](市场温度与下一交易日计划.md)。
- **板型与反馈**：总览炸板前五、封单收盘快照、涨停梯队与连板反馈展示有据高度、板型和量能；反馈默认按已核验昨日高度降序，未知高度排后。同股票详情/K线口径一致，缺证据不生成标签。核对[连板高度、板型与次日反馈](连板高度板型与反馈.md)及[个股成交形态标记](个股成交形态标记.md)。
- **自动只读主线**：所选日原因直接形成重点、其他方向与事件、个股线索及来源缺口；分类家数去重对账，全局高标独立展示。无录入、补证据或待办表单，不读取旧手工归因来决定分类；未知不补0。规则见[界面导览](界面导览.md#8-当日主线复盘)。
- **监管与成员日期**：监管“最新名单”与“指定日历史”分开，观察日、获取时间、股票行情日独立；历史缺档仍未知，供应商区间不当作官方监管期限。板块成员的历史/当前口径分别验收，缺成员不清空已有指数价格；切换只读本地存档，不联网补采，见[板块行情与成员档案](板块行情与成员档案.md)。

### AI官方API与系统网络代理

AI请求默认不继承系统代理。若部署机器访问官方API必须经过操作系统已配置的网络代理，可在后端与唯一worker的部署环境中显式设置`SHIXU_AI_SYSTEM_PROXY_ENABLED=1`；其他取值仍关闭。该开关只控制HTTP客户端是否继承系统网络路由，不开放第三方中转API或自定义Base URL。目标仍固定为`api.openai.com`与`api.deepseek.com`，继续校验TLS证书且禁止HTTP重定向。不要将代理地址、认证头或Key写入日志、前端或验收回执。更改后按既有独立版本流程重启对应隔离或已获授权实例。
