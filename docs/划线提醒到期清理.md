# 划线提醒的监控与到期清理

保存并启用提醒的新线一直监控，未实际触发时没有到期日。首次产生成功提醒或支撑失守风险提醒后，继续监控60个市场交易日；首次提醒日为第0日，之后第1至60日保留。重复触发、改价、改名、修改规则或暂停后再启用，不重新计算期限。

超过上述期限后，在下一次手动创建的盘后增量及其接续划线核验中，删除到期线、该线全部规则版本的提醒事件和逐日核验记录，不另存一份可见的历史提醒。任务仅保留清理数量、业务日及恢复检查点。未触发的线、只有未触发或待核验结果的线、参考线不因保存时间长而删除。首次提醒日期缺少真实交易日历证据时保留并记入待核验数量，不能按自然日推算。

## 对已有数据的影响

- 已有提醒以同一条线所有版本中最早的真实提醒日为起点；升级迁移本身不清理业务记录。
- 已手动删除线的关联提醒，仍按首次提醒后的同一期限清理。
- 到期不删除已加入的自选、策略跟踪轮次、独立价格基准或其他对象持有的来源引用。
- 只解除到期提醒自己拥有的 `line-alert:<event_id>` 引用，不直接删除行情文件、共享快照或已有备份；物理SQLite文件不会因此立即缩小。
- 离线补跑历史事件已经超过期限时，不据此新加入自选。

## 执行边界

新增盘后增量冻结 `line_alert_retention_version=first-alert-plus-60-sessions-v1`，只有该任务接续的唯一worker核验任务可以清理。旧冻结任务不扩大范围；初始化、普通GET、手动检查提醒都不触发到期删除。显式暂停或取消不自动继续。

清理每批最多100条线，短事务内重新核对行情代际、业务日、规则时钟、任务租约、父增量授权和首次提醒日期。事件删除守卫默认拒绝，仅当前worker连接上本批精确的线ID和事件ID可以通过，结束立即恢复默认拒绝。事件不可修改守卫不变。

每批删除与累计数量、规则时钟检查点同事务提交。显式恢复使用原检查点续清理，不重放行情核验；期间外部改线或切换行情代际会停止旧任务。

## 界面与接口

图表划线列表显示“尚未提醒，持续监控”或首次提醒日期与60交易日规则，自选提醒区同步说明。没有额外期限选项或延期操作。

水平线响应增加 `first_alert_date`（尚未提醒为null）及 `post_alert_tracking_sessions=60`。`GET /watchlist/line-alerts` 的 `latest_check.cleanup` 可包含累计删除线数、事件数、核验数、日历缺证据数量和完成状态；不重新复制已删除提醒的内容。

026迁移只新增首次提醒索引并更新受控删除守卫，不更改已有事件值。验证覆盖未触发长期保留、第60/61日边界、重复触发不延长、普通检查不删除、旧任务不扩范围、孤立历史清理、缺日历保留、自选与跟踪不变，以及分批暂停恢复。
