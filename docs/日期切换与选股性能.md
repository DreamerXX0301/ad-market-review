# 日期切换与选股计算性能

日期选择只改变盘面观察日，不改变策略、跟踪或研究的业务日期。性能优化沿用原始报价、完整周/月、历史事件、缺口和公司行动的严格判断；未知不补零，已有结果不重写。

## 指数与盘面读取

指数页改用 `GET /market/indices?date=`。它只读取指定日指数资料及覆盖说明，不构建全市场股票指标，也不核验五千多只股票的历史涨停记录。图表仍使用原有指定日、指定周期和价格口径的图表接口。

总览的近30日排行先对完整股票范围按原收益和未知排序，再为实际展示的前五名补齐历史涨停证据。证据仍按原始256股批次核验，保留原批次覆盖字段；前五缓存不能充当完整可检索、可排序的涨幅榜。资金轮动的行业视图不再预先请求尚未打开的概念榜。

涨停证明只需日期与收盘时，使用最多256只证券的列投影。重复日期和缺收盘保留，读前核验源文件，未改变事件核价标准。补充资料缓存按实际核验的来源身份失效，时间戳相同的内容更正也必须生效。

## 选股执行

一次运行只编译一次固定规则的周期、参数和候选证据需求。普通日/完整周/完整月指标、底部抬高依据及每组BOLL参数分别保存有界技术摘要，合成时深拷贝；题材、身份和跟踪政策不写进共享摘要。不同数据根、行情代际、日期、周期和算法/参数不得互借结果。

在核验实际来源后先探测摘要，只有缺少所需摘要的证券才按原32股上限读取全历史种子。周/月信号命中缓存后，入池仍读取业务日自己的日收盘，不把上一完整周/月的信号价当成入池价。未证明来源身份的兼容读取不能跳过原始历史读取。所有原始指标、缺口原因和已保存候选依据保持原口径。

周线聚合把反复从头扫描日历改为同一排序日历上的二分区间查询，保留完整性、缺失日期、跨周重启和未完成周判断。

## 验证方式与适用范围

使用同一不可变行情、补充来源、观察日、规则版本和证券顺序，分别在独立旧/新进程中串行测量；完整响应及逐股判断依据规范化后对账。首访、新日期、回访和连续策略运行分开报告，不用分析器下的耗时与普通计时拼接百分比，也不把样本推算当全市场实测。

测试覆盖来源损坏、参数与代际变化、缓存淘汰和调用者修改隔离、缺日/零量、完整周/月、历史事件以及旧结果兼容。浏览器另验快速切日期时旧响应不覆盖新日期、行业/概念按需读取和指数图正常加载。

实测数字与最终正式升级状态以本次交付记录为准。首次全市场加载仍有成本；缓存有容量限制，切换行情代际、参数或淘汰后需重新计算。测试不清空操作系统页缓存，不代表所有硬件、并发负载或任意复杂750日事件策略的耗时保证。没有新增自动取数、研究或选股任务。
