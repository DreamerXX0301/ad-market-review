# 自动支撑压力线

个股与大盘指数的K线工具栏点击“划线”，在“自动支撑压力”选择回看60、120或240根当前周期K线，点击“计算候选并预览”。候选会先显示在图上，可以取消不需要的价位，再点击“保存所选支撑压力线”。保存后刷新仍然保留，并可继续改价、改名或删除。重算候选不会改动已经保存的线；重复保存同一次候选不会产生重复记录。

日K、周K、月K分别使用各自的历史结构。周/月仅使用已完成、报价完整的周期；本周或本月未完成的K线不会参与分型确认。各周期统一用观察日最近已发布日收盘划分支撑在下、压力在上，参考报价日期单独标明；不会拿上月末旧收盘把当前价格上方的线称为支撑。候选保留源周期，保存后与同一价格口径的日/周/月图共用。指数按原始点位保存。个股按当前图表的实际未复权或本地前复权口径保存，复权锚跟随当前观察日记录；以后换锚仅在公司行动证据可核验时投影显示，原保存价不被重写。

## 候选怎样得到

算法版本为 `confirmed-pivot-cluster-v1`。一个历史低点必须严格低于左侧2根、右侧2根完整可比K线的最低价，才构成已确认低分型；高点反向处理。右侧第2根的日期是确认日，必须不晚于观察日。相同价格的平顶、平底不会反复计数。缺少交易日报价或整周、整月时不会越过缺口拼接确认；未复权公司行动之后重新划定可比窗口，公司行动来源覆盖未知不生成可比候选。

低分型中不高于最近已发布日收盘的价格作为支撑候选，高分型中不低于该收盘的价格作为压力候选。同侧价位在最大跨度0.8%内聚合，采用组内算术均价；不是首尾不断扩张的链式聚合。每侧按离参考收盘的距离由近到远保留至多3条，合计最多6条。没有符合条件的候选时保留原因，可以扩大回看范围或手动输入价格。

这些是历史价格结构的参考位置，不是保证有效的支撑、压力，也不代表收益预测。图中注明观察日、来源周期、价格口径、参考收盘日期、历史分型数量与最近确认日期。来源窗口内样本少时保持少量候选，不补造6条。

## 保存和原有划线的关系

- 保存候选写入业务SQLite的 `chart_annotation`，不修改日K、指标、策略或历史事件。
- 自动候选默认只有显示用途，不启用提醒，不自动加入自选。个股如需提醒，可在保存后编辑并明确勾选规则；指数不提供个股提醒与自动自选。
- 保存来源含算法版本、行情代际、观察日、周期、窗口、分型与确认日期、原候选价。后续手工改价或改类型会标注“已手动修改”，来源证据继续保留。
- 单个标的与原手工线共同最多64条。批量超限时整批不写入。
- 窗口或行情代际变化需要重新计算。过期预览保存返回错误，不能把旧图的候选静默存到新口径。
- 未保存的预览只存在本次界面，换股票、周期、观察日、行情代际或收起候选后即移除。已保存的线按显式提醒规则保留：未实际提醒持续监控，首次提醒后继续60个市场交易日，超期由新盘后增量清理线及关联提醒；没有启用提醒的候选线不会因保存时间而到期。详见[保留规则](划线提醒到期清理.md)。

## 计算与性能边界

只有用户点击计算或保存时执行本地计算。GET列表只读取SQLite，不联网，也不会自动生成行情任务。保存时先在事务外读取单证券已发布价格并重算核验，再用短事务保存至多6条线；不会打开worker正在写入的DuckDB。计算不调用全市场图表广度或全市场行情面板，不为一个指数候选加载全部股票。

迁移021只增加来源、幂等键和股票/指数类型字段。历史手工线仍为股票标记且来源为空，不会自动改变已有提醒规则。数据库约束再次保证指数无个股提醒、自动自选及个股复权口径；提醒消费也显式只取股票规则。

验收覆盖：严格左右确认、历史观察日与未来数据隔离、D/W/M、未完成周期与缺口、公司行动、价格聚合跨度、有界候选、未知与不足样本、来源价格对账、手工修改保护、保存持久化与幂等、批量原子上限、过期代际/预览拒绝、指数API及数据库约束、旧手工线与提醒回归。
