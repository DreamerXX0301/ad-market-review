# 数据库与数据流

SQLite 保存业务、任务和发布目录；不可变 Parquet 保存行情与分析结果；DuckDB 在进程内查询或合并这些文件。API 与 worker 共享 SQLite 短事务，行情采集和发布由唯一 worker 执行。架构分工见[架构与模块边界](架构与模块边界.md)。

## 迁移与结构

当前迁移包括 `001_initial`、`003_platform`、`004_workspace_policies`、`005_workspace_policy_evidence`、`006_research_cache_ttl`、`007_strategy_trade_rules`、`008_sector_strategies`、`009_sector_tracking` 和 `010_stock_signal_period`。编号缺少 002 不代表漏执行；以仓库实际迁移和校验和登记为准。已应用迁移不可改写，后续变更新增文件。

完整字段、外键、索引及触发器见 [schema-current.sql](../contracts/schema-current.sql) 和 [schema-current.json](../contracts/schema-current.json)。它们由[导出脚本](../scripts/export_schema.py)在临时库应用迁移生成，不包含业务记录或密钥；不能代替运行时迁移校验。

## 文件与事实归属

| 位置（相对配置根） | 内容 |
| --- | --- |
| `business/app.sqlite3` | 业务库、WAL 与任务目录 |
| `published/<market-generation>/` | `raw-daily.parquet`、`daily.parquet`、公司行动、`reference.json` 及清单 |
| `published/market-supplement/` | 独立盘面补充索引及逐日 artifact，不覆盖主代际 |
| `raw/`、`work/` | 来源原响应、accepted receipt、暂存、DuckDB 私有 spill 与可重建派生摘要 |
| 已登记结果快照 | 回测 signals/orders/fills/positions/trades/equity 分账文件 |

路径通过环境配置覆盖，详见[部署与运维](部署与运维.md)。业务库中保存完整证券 ID，例如 `000001.SH` 与 `000001.SZ`，不能仅用六位代码关联。价格/点位持久化的 e8 字段是定点整数；股票金额使用元，板块点位不应标成货币。量额单位由响应声明，不能对所有资产统一乘 100。

来源题材成员保存在固定代际引用文件中，SQLite 保存稳定分类身份和人工覆盖。当前目录、来源成员观察日和股票报价日各自独立。`member_count=null` 表示未证明完整，`observed_member_count` 只是已留存样本；完整空集才是零。

## 发布事务与冻结输入

1. 用户请求生成任务，冻结来源、目标日、窗口与链版本；`request_key` 用于任务幂等，不能改变原参数授权。
2. worker 在事务外采集，保留原始响应与 SHA，验证身份、精确日期、分页、价格、单位及缺口；失败对象单独登记。
3. 写不可变文件和 manifest，验证路径、行数及文件校验和。主行情先文件后 SQLite，在同一事务发布相关 heads 与业务日。
4. 策略与跟踪读取固定代际；保存前重验 SQLite 依赖和任务状态。候选、版本与已记录事件不因后续修改而重算覆盖。

独立补充索引有自己的原子切换与来源证据，不把文件 head 假称 SQLite 发布事务的一部分。一次求值使用固定已载入补充文档；历史运行保存的输入与依据不随当前补充更新改写。

当前源身份不提供完整历史 ST、退市和成分变迁档案。分类或上市日期未知不推断成正常状态；梯队展示的已成交年龄下界也不能回填真实上市日期或放宽回测风控。

## 初始化链、首次锁定与尾部增量

新主初始化带 `data_chain_version=sector-charts-v1`，依次衔接题材、板块全库和盘面补充。新增量带 `sector-charts-increment-v1`，衔接板块尾部与当日补充。旧无标记任务保留原链，不自动扩大授权。显式暂停/取消及失败祖先不会被后续链偷偷绕过。

板块首次状态根据已完成/partial 的 initial 任务及其冻结清单 SHA 判断；只有全部冻结目录代码可用才锁定。来源边界造成的缺首日仍可质量 partial，不能误判为需要无限整库重拉。锁定后 initial 创建、执行、重试和继续均拒绝；日常 increment 不受此首次锁定影响。

初始批次清单与增量批次清单分 namespace，避免无变化增量覆盖首次证明。板块尾部 receipt 记录前段引用、独立新增 raw、合并结果和 SHA；读取逐段复验，有段数上限。新代码没有基底时才做首次全段。历史日期读取先验证原全段，再截到目标日重算 D/W/M、指标和波浪，不能截取已含未来的聚合结果。

## 计算缓存与空间

主行情查询按证券/日期限定并分批处理；严格历史指标共享有界矩阵和 checkpoint，不把全市场多年行情一次转成 Python 字典。个股摘要与成员统计复用固定代际缓存，键包含业务日、候选、精确报价和补充内容；未知日期不以前次结果替代。

板块指标持久摘要绑定来源代码、观察日、代际、目录/日历及算法版本，每次命中仍验证实际 raw/规范化文件 SHA。派生文件损坏、过期或不匹配时重算；缓存可丢弃且有体积边界，不影响原始事实。数据中心计数读取小型状态摘要，不为每次轮询解析全部历史 K 线。

下载增量与磁盘增量不同：主行情合并或题材发布可能复制完整行情代际。旧代际、原始证据、回测结果和备份独立占空间；当前没有默认清理全部已发布历史的自动 GC。不能用一次数据量估计长期上限，应结合更新频率、引用保留和备份策略监控实际占用。

## 清理、备份与兼容

- 研究报告和材料按最后主动访问后七天到期；列表轮询不续期。清理只释放研究自身引用，保留外部 pin，不删除行情、策略或跟踪。
- 业务事件、策略版本、已完成运行及已发布快照受不可变约束保护；政策迁移追加审计，不覆盖旧事件。
- 备份需同时核验 SQLite、被引用文件及密文凭据；主密钥另存。恢复在新目录/卷验证，不就地试迁移唯一副本。
- 显式重建工具保留个股/板块策略及版本政策配置，清空派生运行与跟踪；它是管理操作，不是日常更新，也不会在启动时执行。
- 应用启动会检查并应用新迁移。已有部署先备份并在候选副本验证，再切换；不能把“源码更新”当作可直接覆盖当前数据库的保证。
