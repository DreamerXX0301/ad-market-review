# 存储与盘后增量优化

这项改造分阶段推进，每个阶段独立验收。源码功能、运行实例和自动清理的启用状态分别确认；提交代码不表示已有安装已升级。

## 第一阶段：容量口径与轻量核验

已实现：数据中心使用十进制GB，展开可查GiB、原始字节和六类构成（含共享行情对象）。数字只统计本实例published的普通文件，不包括业务库、raw、work、其他版本和备份。文件块量单列；逻辑重复文件和旧行情代际都不等于可直接释放空间。扫描不完整时明确显示小计，不能把失败目录当作零。

主行情完成后，先给划线提醒和上市身份核验排队，再创建板块尾部任务；重启补漏使用相同顺序。全局队列仍为FIFO，不抢占先前用户工作，不恢复显式暂停或取消的任务。无变化同步先冻结父任务自己的业务日，不能用后来发布的日期替换。已配置的本地策略与跟踪核对仍在唯一worker中执行，实际用时写入父任务事件；这些本地计算和已有排队工作仍会影响轻量核验的开始时间，不能承诺固定30秒完成。

第一阶段不改变行情文件格式，不取新数据，也不执行清理。已有实例应依照[升级与回滚](版本升级与回滚.md)使用独立恢复副本验收后更新。

## 第二阶段：公开资金来源的故障预算

已实现的新手动在线任务冻结 `public-fund-budget-v1`，沿父任务后续链传递；已有任务及其重试继续使用原冻结参数。新模式最多3个在途请求，两轮共用200逻辑请求、600次应用HTTP调用和60秒异步网络截止目标。健康目录维持原覆盖；同类连接、结构、5xx、限流或拒绝连续5次后停止新发请求，不把128个行业一次全部塞进后台执行器。目录与行业请求都支持暂停时取消并等待收尾；第二轮只补暂时失败，永久日期缺口不重复拉，已成功或有效部分历史缓存继续核SHA复用。

两轮使用首个已确认目录的代码、名称和分类指纹。目录缩小或改名时，保留首轮记录、分母、缺口及两轮原始证据并标为部分覆盖，不能因少了失败行业而变成完整。

实际逻辑请求、传输调用、在途峰值、故障类型、未请求代码、缓存及本地校验时间分别记录。未请求、被取消和数据缺口保持未知，不记作零或完整。60秒是共享异步网络截止目标；同步本地缓存、校验、发布和平台DNS收尾可能延长实际时间，因此不能称为整个补充阶段的硬60秒上限。没有运行真实来源增量来宣称全链提速，验证使用隔离合成传输，包括健康128行业全覆盖、持续故障停发、混合永久/暂时失败、目录恢复、共享截止及暂停取消。

既有冻结任务继续使用1.2秒项目保护间隔，710板块范围保持完整。官方[历史指数K线契约](https://fuyao.aicubes.cn/docs/api-reference/a-share-index/)要求单个 `thscode`，不接受逗号列表；批量指数快照仅为最新行情，没有指定日参数，不能代替冻结观察日的历史尾部数据。[官方频率说明](https://fuyao.aicubes.cn/llms.txt)采用动态限流，未承诺固定QPS；1.2秒不是官方公布的硬下限。710次串行请求按原间隔，仅709段间隔就需要850.8秒，端到端还包括网络与本地工作。

### 0.1.9板块尾部请求节奏

新手动盘后增量冻结 `sector_tail_request_policy_version=sector-tail-pacing-v2`，仅在板块增量子任务中采用0.6秒全局发起间隔，仍然串行、最多1个在途请求。实际传输尝试也受同一时钟约束，不借多个客户端绕过间隔。来源4001/429限流、2001/2003认证权限拒绝或HTTP 401/403立即停止新增请求，缓存继续复验；其他暂时错误仍最多3次尝试并有限退避。等待与退避检查原暂停、取消和行情代际guard，离开作用域即恢复默认来源策略。旧冻结父/子任务不升级节奏，首次整库、单板块、主行情与盘面补充仍使用原策略。

用户授权的真实窄探测覆盖5个行业、5个概念的同一个已验收交易日，每次只请求该日尾部，合计30次、每次1个传输尝试。按原“响应结束后1.2秒”节奏的10项为11.933秒；按“全局发起间隔0.6秒”的两组分别为5.504、5.533秒，全部30个数据内容SHA与原验收响应一致、失败和限流均为0，实际在途峰值为1。约2.16倍仅为这10项短样本的网络调度结果，不能证明同账号可长期保持该吞吐，也不是710板块含SHA复验、合并、指标预热和发布的端到端实测。理论709段0.6秒间隔为425.4秒，实际时间还取决于响应、重试、本地计算与用户中断；不能承诺固定完成时间。

所有原始探测响应、请求参数与时间回执仅留在忽略的私有运行目录，不进入发行内容。完整全库在线链收益须在实际手动任务中另行验证；短样本与离线重放不等于正式部署或全链实测。

### 板块尾部采集与本地派生复用

板块批次在一次任务内固定目录身份、市场日历与行情代际，复用小型逐板计划；上下文退出即释放，不能跨日期或行情代际使用。旧读取器若在任务中改变目录或日历，重新走原规划校验。该上下文最多800个计划，不保存全库历史报价。

尾部采集每验收一个板块，就在下一次串行来源请求之前准备该板块的日、完整周、完整月指标。此计算可利用原1.2秒请求间隔中的空闲；不新增线程或并行来源请求，也不缩短间隔。记录交接只使用当前进程内的私有核验标识，并重新核验记录、指针、日历及全部实际来源文件SHA；来源数据、覆盖和批次清单不因派生缓存状态而改写。首次下载或不支持该标识的旧路径继续在全批次完成后预热。末尾仍核验派生摘要确已持久留存，失败只提示可重算，暂停、取消与代际变化仍立即停止。

同一个有界、可丢弃的板块指标摘要可另留精确T/T−1两条日线，供后续盘面补充复用。每次消费仍核验完整来源闭包SHA、当前目录身份、目标日期及两行摘要校验值，再执行原日行情归一化；不能用近似日期、当前成员或指数成交额代替缺失数据。摘要损坏时回到原始来源链重算；实际来源损坏仍保持失败或未知。此为本地重复计算优化，未实测新的在线请求整链，不能将离线重放耗时当作盘后在线完成时间。

### 任务内HTTP连接复用

唯一worker的一次显式任务使用独立连接作用域，同来源及同凭据复用HTTP连接；结束、失败、暂停或取消退出时统一关闭，后续任务重新建立。作用域最多8个来源/凭据组合，每个连接池最多1条连接和1条keep-alive；不持久化Cookie或Key，不在进程全局共享账号状态。能力验证的一组小请求也使用相同边界，作用域外的单次调用结束即关闭。

连接复用不提高来源请求并发，原45秒读取/12秒连接超时及最多3次尝试保持；失败尝试同样计入来源间隔，429、5xx和业务限流仍有限退避。供应商对象存储下载继续使用独立白名单与无账号Key的流式请求，不能把账号认证转发到下载域名。测试用隔离传输验证710次逻辑请求复用一个客户端且保留709次间隔，不把省去客户端构造次数等同于真实网络耗时收益。在线整链时间仍受来源延迟、限速、缺口和队列影响。

### 本地合并校验的日期转换

主行情合并核验先为去重后的原始毫秒时间键物化上海日期映射，再按原时间键关联全部证券，避免在全历史覆盖关联中为每行重复转换时区和格式化日期。仍使用原转换表达式；非午夜报价、同一日多个不同时间键、上市及退市边界、未知身份和历史修订均沿用原覆盖判断。旧包与新包的原始校验、缺交易日拒绝、写出排序、编码和SHA要求不变。

该优化仅减少本地合并阶段耗时，不改变请求数量、来源间隔或后续数据链。评估盘后速度时分别报告主行情下载、合并校验、板块尾部采集、指标预热与盘面补充；本地阶段的收益不能直接当成整条在线增量链的提速。重放留存数据时不得声称完成了一次新的在线增量。

板块日线和完整周线的本地指标预热复用最新两期输出优化，全部历史递推、月线完整性和来源SHA核验继续执行；没有省略预热，也不将原始采集失败改记为缓存成功。

## 第三阶段：跨版本共享对象已接入

新创建的手动初始化、盘后增量和题材刷新冻结 `market-partitions-v1`。历史日K以月份保存为内容寻址对象，新代际只列出固定 SHA；未变化月份复用，新交易日或历史修订只生成变化月份。原始格式和统一格式分别保留，类型、数值和复权口径不变。参考资料也拆成共享字段、证券目录列和指数月份，不能把每天重新写一份完整目录当作增量。

旧单文件代际、原来源 SHA、策略和报告仍兼容，不原地改写。新旧 reader、历史入池价、上市身份、覆盖核验、题材刷新、股票/指数图表统一使用解析器。单股日周月浏览复用固定行情代际的有界 16 项报价缓存；切换代际会清空，返回行另复制，不改变指标或策略算法。逐股查询只复用本实例固定代际的 DuckDB 内存连接和 Parquet 元信息，受同一可重入锁串行保护；禁用外部文件页缓存，不打开 worker 的分析库。切代、整表缓存接管、关闭或读取失败会释放连接与私有临时目录。固定分片清单结构另有 64 项有界缓存，每次读取仍复核实际对象签名、SHA和共享目录的符号链接状态。

按股票与日期批量取历史时，若同代完整Arrow行情已被盘面页加载，只切请求股票和日期范围，并投影真实原始日K列，不重复扫描Parquet，也不把公司行动或涨停核验等衍生列塞入原接口。没有完整缓存时仅把日期范围对应月份交给DuckDB过滤，不能为了短期批量查询先加载全市场历史。

标准备份包含轻清单和所有实际共享对象，一份对象只复制一次，恢复后不依赖旧数据根。若存在未完成的行情GC或 `gc_pending`，备份明确拒绝，须先完成原清单恢复；不能把删除中间态打包成完整回滚。格式、容量六类口径和引用回收条件见[共享行情存储契约](../contracts/market-storage-v1.md)。

### 旧实例转换

先按[升级与回滚](版本升级与回滚.md)完成独立候选恢复、停止该候选 API/worker。只在候选根运行：

```bash
backend/.venv/bin/python scripts/compact_market.py \
  --source-data /已冻结的标准备份 \
  --generation market-明确旧代际ID \
  --output-data /独立恢复候选数据根 \
  --receipt /私有验收目录/存储转换.json \
  --register --offline-maintenance
```

该过程校验旧 manifest/逐文件 SHA，为原始和规范化日K分别做全量逐行对账，生成新代后登记显式本地维护任务。没有网络请求，不自动运行历史策略或提醒。已经验证的相同转换可以幂等复用，不能用另一个来源冒充同版本。目标至少预留 1 GiB 空间；真实历史窗口、DuckDB spill、备份另需空间。

登记后市场代际改变，盘面补充必须用已有原始证据本地重验再发布到新代；不盲改补充 head。旧策略和报告继续指向原代，不随迁移改写。

### 真实静态验收和容量解释

在隔离目录重放相邻两个真实行情日，原始及规范化各六百多万行逐行一致；12 个股票/指数样本的 D/W/M 图表指标也逐项对账。详细行数、时长、增长字节和性能条件保存在私有验收回执，真实采集响应和截图不进入公开仓库。测试数字仅代表对应输入；全量逐行验证时长不能宣称为日常增量耗时，OS 缓存没有清空也不能称作冷盘基准。

最终8192行组编码的静态相邻日样本（2026-10-22至10-23），首次独立共享行情约269.49MB，后一天的组成如下，均为十进制MB：

| 范围 | 本次增加 |
| --- | ---: |
| 主行情published，包括变化月、参考对象、小清单与公司行动 | 5.228MB |
| 该代catalog登记文件 | 0.402MB |
| 保留的真实accepted来源响应 | 2.940MB |
| 派生清理小回执 | 0.221MB |
| 上述主链小计 | 约8.79MB |

该小计不含盘面补充、板块K线、SQLite、研究/回测、其他任务小文件和备份。若仅作单样本线性外推，假设一年242次交易日更新、业务和来源结构均不变，主链约2.13GB/年、五年约10.64GB，另加首次历史、其他能力及保护对象；它是容量参考，不是固定预算，也不是已经运行一到五年的实测结果。

另独立抽取200只证券，覆盖短历史、报价缺口和公司行动，共600个D/W/M周期、4800项条件判断，行情证据、严格指标、条件结果和BOLL参考全部一致，未展开全市场Python数据。该轮旧格式29.033秒、新格式30.407秒，中位每股160→176毫秒，最大587→295毫秒，进程峰值约258MB。单次样本总时长仍有4.7%差异，不能宣称所有读取已提速或完全无回归。

长期容量必须分开估计：共享的有效历史、仍被历史业务引用的修订对象、原始来源证据、SQLite、盘面补充/板块K线、派生工作文件、升级备份。参考资料、每天发生多少 IPO/名称变化、回测次数和历史 pin 都会改变增长，不能以一天样本承诺固定一年或五年体积。未变化五年历史不再每天完整复制；全部版本都被长期保存时，变化月份及业务证据仍会累积。

`scripts/compare_market_partitions.py` 保留为早期受 SHA 固定的离线分片实验工具；它不代表现用实例已经转换。实际格式转换使用上面的 `compact_market.py`，源码已实现与正式实例已升级仍分别验收。

## 第四阶段：五年活动窗口与引用回收

每次成功发布以主行情业务日滚动五日历年活动窗口，head/API 同时保留 `active_begin/end`、`physical_begin/end` 和被保护的指标种子范围。任意参数 MACD/KDJ 递推、完整周月及历史事件不能统一截成 250 日；当前精确前缀作为种子保留。`data_begin` 仍反映真实保留起点，不把活动范围冒充已删掉的文件。

已实现的回收入口仅用于明确的离线维护窗口；默认不在 API 请求、任务完成或后台启动时自动删代际。先生成计划：

```bash
backend/.venv/bin/python scripts/market_storage_gc.py \
  --data-dir /独立恢复候选数据根 \
  --plan /私有验收目录/行情回收计划.json
```

确认目标 API 与唯一 worker 均已停止、计划引用及业务对账正确后执行同一清单：

```bash
backend/.venv/bin/python scripts/market_storage_gc.py \
  --data-dir /独立恢复候选数据根 \
  --plan /私有验收目录/行情回收计划.json \
  --apply --offline-maintenance
```

中断后用同一计划追加 `--resume-collection 原collection_id`；新增业务引用会阻止继续。旧代缺文件、类型或 SHA 不符、未登记文件、未知恢复依赖等情况拒绝清理。头、有效 pin、策略/运行/跟踪、自选、划线 origin、提醒证据、报告、暂停任务及传递依赖保留；默认最近两代继续可用。已清理行保留不可变元数据和逐文件审计，通用 `validate` 能区分授权缺失与损坏。

活动窗口、对象回收、业务回收站、升级实例和备份保留各自独立。不会通过这项功能清空策略、回收站、备份、源响应或手动资料；“五年活动数据”不承诺整个磁盘固定不增长。

## 成功发布后的合并派生副本

只优化 `published` 不够：旧实现每次把增量响应和旧行情合并为 `raw/sync/<job_id>/year.parquet`，这份近五年派生文件约115MB；题材更新也曾在 `work/<job_id>` 复制同样的完整行情。它们是本机合并/规范产物，不是提供方原始下载响应。新冻结 `market-partitions-v1` 任务在成功登记发布后，以 `published-market-derivatives-v1` 释放这些可重建副本。

释放前核验任务已经成功发布相应 `daily_raw`，其已登记分片清单与SQLite SHA一致、原行情分片闭包的SHA/大小/行数/范围一致，`year.parquet` SHA等于该代来源清单。仅处理明确的 `year.parquet` 和该代 `supplemental_hashes` 已登记、逐项匹配SHA的规范文件；真实网络响应、手工资料、未知文件和其他任务路径不进入清理范围。成功路径不额外运行全历史 `EXCEPT ALL`，以已验证写入器与不可变原行情闭包为依据，并记录耗时。

同步任务的 `accepted/*` 原始响应继续保留；题材任务虽然把原响应写在 `raw/`，但 `topic-plan.files` 明确列出的原始文件同样受到保护。小回执 `derived-cleanup.json` 留下原合并文件SHA、原始响应SHA/大小、已发布原行情清单、逐文件冻结路径及pending/removed/absent结果。中断可沿原清单恢复，文件、来源或清单变化会停止。释放失败仅记录告警，不把已成功发布行情改成失败。

旧冻结任务、暂停、取消、失败及未登记发布的任务保留原恢复材料，不自动清理。重复更新同一日且SQL已核验行数不变、重叠修订为零、证券身份未变的新任务直接跳过完整合并文件COPY，也不生成规范master/calendar副本；本次实际获取的原始响应仍保留。来源漏跑超过短包覆盖时可能需要重新获取全量来源包，这是真实原始响应，不能按派生文件规则删除，容量另行计算。

## 补充数据的250交易日窗口（0.1.6）

盘面补充与主行情活动窗口分开管理。新手动任务冻结 `supplement-retention-250-v1`，在成功发布后按含观察日的250个市场交易日裁剪盘面补充并回收确定无引用的文件；年度统计、独立五年K线来源、已有业务引用和恢复证据继续保护。不会按文件年龄删除，也不据此承诺整个实例磁盘容量不再增长。逐项规则、删除预算、并发保护、恢复回执与阶段性能实测见[补充数据250交易日保留](补充数据250交易日保留.md)。


## 龙虎榜独立30交易日窗口（0.1.11）

龙虎榜日榜和买卖席位独立保存在 `published/dragon-tiger/` 的不可变对象中，小型发布索引引用每日规范对象及对应来源响应SHA。单日榜和三日榜分别标明区间，多披露原因不混加；API只按选择日读取本地索引及该日对象，不展开30日全部内容，也不联网。读取不能代替采集，已有安装须手动补齐，新初始化及新盘后链使用冻结能力标记，旧任务范围不扩大。

窗口按已发布市场交易日向前取30日。最新日完整验收后才推进发布锚；失败保留未知及可重试材料，不使用请求日期提前推进清理。唯一worker在发布成功后按引用闭包保留每日对象、来源对象和必要断点材料，再清理已无引用的窗口外对象。部分日完成的回补仍以实际验收锚为准。盘面补充250交易日、个股/指数/板块K线五年政策互不替代。

标准业务备份和恢复包含龙虎榜发布索引、日期对象、来源对象与必要断点引用，逐个核验SHA及依赖闭包；原始请求调试日志仍属于额外私有证据。30日是活动数据窗口，失败任务恢复所需或其他引用保护的数据可额外保留，不能把估算窗口乘法当成实际磁盘上限。每日金额、披露次数和多原因数量不同，容量以数据中心与实际文件统计为准。
