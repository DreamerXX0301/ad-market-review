# 关注池盘中监控

本模块独立于盘面观察、策略跟踪轮次和盘后收盘提醒。固定版本 `intraday-monitor-v1`，来源扶摇 A 股批量行情快照。普通读取、刷新、保存设置、标记已读不取行情，不创建策略轮次，不修改自选或手动画线，不发布正式日K。

## 范围与开关

配置固定键 `intraday-monitor-config-v1`：`enabled` 默认 false，`revision` 默认 0，`interval_minutes` 固定 10；`scopes` 为 `tracking/watchlist/manual_lines/gainers_30d` 四个严格布尔值，默认均 true；`manual_enabled/automatic_enabled` 默认 true。保存完整配置且显式开启后，唯一行情worker才可创建盘中采集任务。至少一个范围、一个价位来源；版本冲突409，非法、缺失或额外字段422。

范围为跟踪中股票、独立自选、启用非参考划线提醒的股票和已发布30日涨幅榜前1000的并集。同股多策略、多条线、多来源只取一份报价。30日榜沿用正式T/T-30市场交易日价格排名及停牌/除权口径，未知端点不补排名；只取真实rank 1..1000，不补足不足的名单，不创建持久化跟踪轮次。按最新已发布行情代际由worker准备有界小缓存，盘中任务冻结该名单及基准日，不用盘中涨幅改写30日排名。

第一版最多2000只。超限显式阻止启用/采集，不悄悄截断。30日榜冷缓存的数量为null及待准备原因，不当作0只；启用前要求所选范围已准备。范围、规则或代际在采集中变化时停止旧结果发布，下一时段重新冻结。

## 读取和设置接口

所有路径前缀 `/api/v1/intraday-monitor`。

| 方法/路径 | 行为 |
| --- | --- |
| `GET /intraday-monitor` | 今日总览、设置、worker状态、真实范围计数、最近批次、已加载股票与最近100张提醒卡；不取数 |
| `GET /intraday-monitor/summary` | 当前服务日期、`server_now_ms/enabled/total/unread_count/items`，最多5条，不扫描股票历史 |
| `GET /intraday-monitor/events?date=&limit=` | 按事件实际交易日读取，limit 1..500，默认200；独立返回date、chart_as_of、total、unread_count与items |
| `PUT /intraday-monitor/settings` | 完整提交 `expected_revision/enabled/scopes/manual_enabled/automatic_enabled`；返回完整已保存配置；不立即采集 |
| `POST /intraday-monitor/events/read` | 显式提交1..200个event_ids，仅将这些卡的当前版本标记已读；GET不修改已读 |

总览date是服务的上海日期，提醒按实际事件交易日归档；`chart_as_of` 是最新已发布收盘业务日，不与盘面view date联动。盘中采样不冒充今日完整日K；股票名打开已有正式K线，观察日使用chart_as_of。事件依据可独立展开。

股票/事件附当前已发布日的板型、30交易日与年内收益、近30交易日/近一年滚动/年内涨停次数、最近已确认涨停及距离；三种次数口径分开。缺覆盖保留null、原因和已确认下界，不填0。股级数值指标由worker对固定行情代际预热，HTTP只读SQLite小投影。行业概念每次按当前业务日读取，独立标明归属日及来源，不作为历史触发原因。页面支持股票/代码、行业概念、板型与单项指标区间筛选，并提供未知值选项；筛选先于排序分页，提醒列表明确已加载范围。

## 调度与真实采集

唯一worker在既有自动任务之后、队列空闲时检查。时区固定Asia/Shanghai；09:30为开盘基线，09:40至11:30每10分钟，13:10至15:00每10分钟，共25档。只在已核验真实交易日创建当日任务；周末不猜交易日，节假日及日历缺口由来源回执决定。

每档前60秒可登记，采集验收截至计划时刻后120秒；超时不接收迟到报价、不追补旧时段。同档交易日/时隙唯一，重启沿用原批次；失败、暂停、取消不复制任务或自动重试，通用手动任务入口不得绕过自动授权。暂停/取消保持停止，恢复/重试入口不补历史。长任务可能造成缺档，界面显示延迟，下一有效采样重新建立连续性。

取数按明确股票列表每批100只、最多20次请求，串行、有界请求与超时进行，不逐股请求历史，不反复计算全历史指标。网络取数、文件SHA和规则计算位于SQLite写事务外。保存前再次核验租约、设置修订、范围、规则、来源代际和有效时窗。

扶摇快照时间只证明整批最新上游有效时间，单股成交时间未知。分别保留`source_time_ms/received_at_ms/quote_time_ms:null`，标明`quality=batch_time_only`。缺报、重复/额外身份、零量额、无效OHLC、错日、未来超过5秒或过旧批次、除权不可比保持unknown，不补旧报价。涨幅百分数与人民币元/股单位沿用来源并对账。

## 价位和提醒状态

自动水平支撑区、压力区与量价参考从严格前一市场交易日的完整可比序列准备，日内冻结，不随下跌重新寻找更低支撑。真实结构支撑与风险线分别标识。已有逐股profile/max_risk_pct偏好及匹配风险锚复用；默认一周短线风险上限5%，保存锚只抬不降，已失守或不可比不自行重武装。此模块不改原盘后规则的开关、触发记录和到期时钟。

手动线保留annotation_id/revision/原价口径/锚，必要时换算至前一完整日原价，再与盘中原价比较。盘中源前收与已发布前收不一致时暂停比较；前收一致不声称今日全部公司行动已完整核验。

首次采样、规则改版、时隙缺口只建立状态，不伪报刚突破。相邻采样可记录触及支撑、站回支撑、支撑/风险失守、越过压力、回落压力区，再次满足补充holding状态。使用明确缓冲，累计全天high/low不能证明采样之间的先后路径。盘中只称采样观察或连续保持，不称日线收盘确认。

同一股票、同类型、重叠价位且同一轮变化的来源可合成一张卡；每条来源独立记录规则版本、实际采样时间、源批次时间、前后样本和冻结价位证据。跨日与同一规则重新越过使用不同episode；已有卡不得因宽区间桥接而吞并不相交价位。新增依据和holding更新原卡，原始来源回执不可修改。已读后新增依据可再次未读；浮层仅提示新event_id，首次加载历史、同卡更新不重复弹出。

## 池内热点派生视图

前端对当前名称、板型、指标范围等筛选后的股票集合，按明确`topic_id`及当前归属日聚合行业、概念和人工题材；未知归属不按名称猜测。同股在单组内去重，跨概念可重复归属，不将分类家数相加冒充独立股票数。盘中、30交易日、年内分别使用通过日期校验的真实收益，缺失不填零；展示有效样本覆盖、上涨占比、涨幅中位数与均值、≥3%家数及领涨股，默认有效样本至少3只。提醒股数优先使用逐股全量`today_alert_count`，兼容旧响应只计已加载事件时必须标明范围。分组钻取使用精确分类身份并保留其他筛选。这是池内个股广度与涨幅统计，不是全市场排行、板块指数或净流入。

总览只公开指标的规范字段、必要覆盖回执和`metrics_reasons`，不重复传送兼容别名；当前分类保留身份、名称、类别及来源日期，省略内部成员维护字段。全部价位与事件证据继续保存在独立回执中，不因列表压缩改变计算或来源保留。

## 存储、清理与恢复

045迁移新增独立batch/baseline/state/event/evidence表；不迁移或合并跟踪轮次。SQLite保存最新状态、批次小清单、事件卡和独立不可变来源回执。每股最新的小基准与风险锚独立保留，旧基准历史滚动清理；风险锚的原始代际持有独立来源pin，不因普通报价到期失去依据。每批报价一份不可变Parquet、原响应一份压缩JSON，按日期/批次保存，不按股票制造文件。同一报价供多条规则复用。

先在work准备文件和SHA清单，登记精确清单后复制到目标文件系统内临时文件、fsync并原子发布，兼容work/raw/published独立挂载。中断后只恢复原清单及原来源，不重新取数覆盖已保存原件。

普通采样保留最近20个真实交易日，事件保留最近60个真实交易日（均含当前交易日）；事件引用的整批来源保护至事件到期。唯一worker在采样发布后及空闲维护时分批清理，清理每文件先登记pending、删除后登记removed，硬中断可按原路径/SHA恢复。未完成/暂停任务、备份引用受保护；不按目录年龄扫描删除，不每10分钟VACUUM。SQLite删除只回收可复用页，不承诺物理文件即时缩小。

标准备份按捕获SQLite精确枚举quote/raw闭包并核验SHA；恢复关闭盘中监控并递增修订，清除可重建的当前状态/基准，保留事件与来源证据。密钥外置；新安装、独立预览和恢复副本均不继承自动采集授权。真实盘中时效须在交易时段验收，合成测试和休市快照不能替代。
